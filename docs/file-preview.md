# Workspace sidebar and native file preview

The right-hand workspace sidebar opens from the chat's `sidebar.right` button, **Window → Toggle workspace sidebar** (default ⌥⌘P), or **File → Open file in preview…** (default ⇧⌘O). Its minimum width is 400 pt for dragging and saved-width restoration; very small windows still share the available width with the conversation. The existing ⌘O shortcut still adds a project. Chat file links, non-image attachment thumbnails, read/edit tool context menus (including grouped reads) and the changes view's **Open current file** action use the same pane. Image attachment thumbnails in the composer and sent prompts open a large preview at the click instead; its **Open in preview** action opens the same pane. Dropping files onto the pane opens file tabs; dropping onto the chat keeps the existing attachment behavior.

## Panels and review

**Browser** embeds Chromium with conversation-owned web tabs, navigation, find, downloads and OMP attachment. Its native hosts survive sidebar and conversation switches; this differs from file readers, which release inactive document rendering. See the [browser lifecycle and automation contract](browser.md).

**Context** is a live, read-only inspector. It shows OMP's current context capacity and native system prompt/system context/skills/tool/message breakdown, an independent estimate of the latest observed agent request (or a clearly labelled current-session projection), the provider's reported request input/output/cache/reasoning, and cumulative accounting from all retained branches of the selected native session file. The [context data contract](OMP_INTEGRATION.md#context-inspector-data) explains sources and accuracy boundaries. Automatic refresh runs every five seconds only while this panel, workspace and window are presented and the conversation is running or has native work. Work ending triggers one final refresh without waking a stopped OMP process; periodic polling then remains stopped. Automatic/final reads never change the Refresh button’s state. Opening an idle panel loads saved snapshots without waking OMP; manual refresh remains available and alone shows a busy button. Same-session refreshes preserve expanded category names. Archived chats and workers read their own saved journal without restarting OMP. New empty chats wait for their first message. Wide panes place composition groups and request/accounting sections in two columns; narrow panes stack them in a native scroll view.

The Context toolbar uses the other panels' insets without a heading, time label or bottom divider. Its right-aligned Chrome capsule groups Information, Copy, Export and Refresh. Copy produces a localized Markdown report; Export offers Markdown and JSON in a native save dialog. Both freeze the selected conversation’s accepted values, including category names hidden by collapsed rows, with separate source times for estimates and provider reports. Unknown Markdown values remain `—`; JSON uses `null`, numeric token/cost fields, explicit source/scope markers and `schemaVersion: 1`. Reports contain metadata and counters instead of prompt bodies. Default filenames include a UTC snapshot timestamp. Click Information to open the measurement notes in a native popover anchored to that button; the notes no longer occupy the bottom of the content. The popover closes when the panel is hidden.

The sidebar shares one horizontal tab strip for fixed panels and file previews. Its control row uses the conversation toolbar's capsule height and top inset, keeping the tabs and action buttons on the same horizontal centerline. Tab close controls use small plain xmarks without a background and retain their click targets. **＋** is a plain icon without a circle background, changes to the accent color on hover, and opens a scrollable panel picker without a heading; selecting an existing panel focuses its single tab. Tabs offer close, close others and close all through their context menus. Closing the last sidebar tab collapses the sidebar and exits workspace fullscreen; reopening shows the picker in split layout. New chats initially show **Files**; existing saved file tabs and reading positions migrate automatically. Each chat retains its panel selection and review turn, independently of other chats. File tabs have no count limit; the window retains at most 24 chat states.

The expand button beside the sidebar toggle enters **workspace fullscreen**, keeping the left conversation sidebar as it is. The current panel or file fills the remaining workspace. The conversation title, prefixed by the `message` symbol, becomes a peer tab at the start of the same strip, with no close action; selecting it shows the conversation and composer across that area. The existing chat controls move to the right of the shared tabs, followed by the fullscreen and sidebar toggles. The conversation tab's context menu retains copy-title and rename actions. **＋** follows the tabs and continues to open the panel picker. Exiting fullscreen restores the saved split width and the last sidebar destination; hiding the sidebar also exits fullscreen. Closing all original sidebar tabs, including while the conversation tab is selected, exits fullscreen and collapses the sidebar. Fullscreen is saved separately for each conversation in the existing preview-state file. Opening that conversation again, including after restarting the app, restores its fullscreen layout and focuses its conversation tab; new conversations use split layout. A fullscreen conversation reopens its workspace even if another conversation previously folded the sidebar. Hiding the sidebar, explicitly exiting fullscreen or closing its last sidebar tab clears only that conversation's fullscreen preference; reopening that sidebar then uses split layout. Older saved states default to split layout. A layout choice made while disk restoration is pending takes precedence over the saved choice.

In fullscreen, Git and Debug initially keep their usual full-width overview. Selecting a file, commit or debug step leaves the list in the left column and opens its detail in the right column, without a Back button. The divider can be dragged or adjusted through accessibility; Git and Debug independently retain their column proportions in the current chat across tab switches and fullscreen exits/reentry. A narrow window clamps both columns to fit without overwriting the remembered proportion. Nonfullscreen keeps the existing single-column drill-down and Back navigation.

The native conversation and sidebar hosts retain their identity across layout changes. The hidden conversation pauses visible-only work; selecting its tab cancels pending file opens and stops the hidden reader. File reading state and the retained Files/Git pages follow their existing tab-switch lifecycle. Preview-tab keyboard shortcuts include the conversation in fullscreen, while ⌘W cannot close that permanent tab.

Files, file previews, Review and both terminal locations share the file-preview toolbar insets: 8 pt above, 9 pt below and 10 pt horizontally. No horizontal divider separates the tab strip, panel toolbar and content; the bottom terminal uses the same divider-free toolbar. Selected workspace tab titles change color while retaining regular weight. Each reader keeps its own internal document/list margins.

The Files page has one toolbar below the sidebar tabs, with no second directory-navigation row or redundant browse button. Parent and Home buttons share the left navigation capsule with a noninteractive current-directory label, whose folder icon sits immediately before its name. Home returns to the workspace root. Narrow toolbars truncate the directory name in the middle while retaining its folder icon and both navigation buttons. The label's full directory path is available on hover and to accessibility. Hidden-file visibility has its own capsule; open-file, Finder and more actions form the file-operations capsule. Navigation and visibility use the same retained browser state as the tree. File-specific more-menu actions appear only when a file preview is active.

**Files** retains the directory tree and native preview actions below. **Review** shows attributed changes from one conversation turn, defaulting to the most recent turn with file changes. The turn menu also offers **All changes** for the conversation's complete attributed diff; this selection survives panel visits, conversation switches and restoration. Previous/next controls share one capsule on the left and navigate individual turns; both are disabled while **All changes** is selected. The completed-turn card's **Review** action opens this panel on that turn; the existing whole-thread changes and tool-detail popovers remain available. **Terminal** uses the same native SwiftTerm component as the bottom panel, with independent per-chat session groups, selections, focus requests and visibility. Both locations can remain open together. Direct sidebar opening creates or resumes its own group without selecting the conversation's terminal button. That button, the menu/command-palette toggle and ⌘J always control the bottom panel. Hiding or closing one location preserves its shells and does not toggle the other. Terminal session tabs and new/restart/close actions operate only on their own group; prompt Escape hides its own panel.

The sidebar toolbar's **Open terminal in bottom panel** and the bottom toolbar's **Open terminal in sidebar** explicitly move all source sessions and their selection to the other location, then close the source panel (removing the sidebar terminal tab when moving to the bottom). Existing destination sessions remain, followed by the transferred tabs. Each transferred shell keeps its process, current working directory, native view and output; no shell restarts. A later direct open of the emptied source location creates a fresh independent group. Conversation deletion closes both groups.

**Git** browses the current conversation's actual repository/worktree independently of Review's turn attribution. Its single toolbar row owns view/group/reference selection, search, back, refresh and the more menu; narrow views compact selectors into icons. Changes distinguish index, working tree, untracked files and conflicts. Clicking a file opens its read-only comparison; clicking a two-line graph row opens commit details and its files. In fullscreen, commit-file comparisons expand within the right-hand commit detail, so its file list and the left-hand graph remain available without Back. Selecting another file replaces that inline comparison; clicking the expanded file row again collapses it and cancels any pending comparison. Disclosure arrows show the expanded state. Expanded inline diffs omit their own filename header and use the file row as their title. Inline diffs in commit details and the staged-commit composer use horizontal margins to distinguish them from the surrounding file list, without a container background or border. They fit short content and scroll internally beyond a 360 pt maximum height. Merge details select a parent explicitly from the toolbar. Search highlights history matches without removing intervening topology. Graph lanes can be dragged horizontally or moved through toolbar commands; widening the sidebar is explicit. Load-more and deferred-diff actions also stay in the toolbar.

The history selector shows **All branches and tags** for the complete scope, the selected reference name for a named scope, or the current branch for **Current checkout**. It truncates the title in the middle when toolbar space is limited, keeping the branch icon, title and dropdown arrow visible; hovering reveals the complete title. The root lists omit the repository name. Changes keeps only the branch on its first content line, using the interface font instead of monospace; History has no repository/branch header or separate scope row. Operational notices, write outcomes and unavailable automatic refresh still appear when needed, without reserving space when absent. The reference popover fits the longest branch/option using the current interface font and shared choice-row spacing, with the shared menu's 210 pt minimum and the screen as its upper bound. Short lists shrink again; only names exceeding the available screen width wrap, without ellipses. It has no search field or footer hint; all loaded references remain available in its lazy scrolling list.

File status markers use yellow for modified, green for added, red for deleted, blue for renamed, purple for copied, pink for type changes, cyan for untracked and orange for conflicts. Rows without a directory/rename subline omit the empty text and center the filename vertically within the row. Standalone file-diff headers show only the filename, with the complete path available on hover and to accessibility; comparison labels, counts, rename descriptions and commit/parent identifiers are omitted there. History's second line groups its metadata at the leading edge with a shared interface font and baseline. Its age labels reuse the sidebar's short format: **now** below one minute, then completed minutes, hours or days, and a calendar date beyond one week. Only the labels observe the shared minute clock; seconds are never displayed. Commit details place the author and date on one row and retain the divider above their file list, without a parent-comparison explanation or a Changed files heading. Parent selection remains in the toolbar menu.

History walks pinned commit tips in topological order, including HEAD, local/remote branches and commit tags while excluding internal checkpoint refs. Pages append without changing the earlier graph rows; pending parents keep continuation lines. History displays at most 2,000 commits with an explicit scope-narrowing message at the limit; a layout exceeding 512 lanes or 200,000 row segments also requires a narrower scope rather than collapsing topology. Search covers the loaded history and reports that scope explicitly. Each Git result is bounded to 8 MiB, file patches to 4 MiB and commit messages to 64 KiB; truncated records and invalid UTF-8 are errors. Large diffs retain the shared parser's initial 1 MiB/20,000-line deferral, with explicit toolbar expansion. Text comparisons disable external diff/textconv drivers and never stage files or create checkpoints. Conflicts compare index stage 2 with the working copy when that stage exists; other shapes explain the missing side and retain the current-file opening action.

Only the visible Git page observes working files, its resolved per-worktree Git directory and shared refs. Changes are coalesced without polling or network operations. Visiting another open sidebar tab or the panel picker keeps the current workspace's Git page mounted, hidden and noninteractive, with its root list, one current diff and one parent commit detail; pending reads, message generation and observations stop. Returning shows those accepted snapshots immediately while revalidating the repository and comparison in the background; writes remain blocked until repository revalidation succeeds. Closing Git, changing workspace, hiding the sidebar/window or covering the workspace with Settings releases detail/diff buffers; small per-conversation navigation and drafts survive in memory. Request generations and repository identity checks reject old completions and a removed/replaced worktree. External Git writes remain external; a detected change during a mutable file comparison requires a refresh. The panel also supports the local staged-commit workflow below. Remote writes, stash, discard, amend and operation continuation remain outside this panel.

App activation and filesystem refreshes revalidate the repository in the background without a refresh-status row or transient refresh-button disabling. Accepted details and diffs remain visible during those reads. Identical results preserve the mounted content, including an explicit large-diff expansion; changed results replace it, and failed reads report the error. Changed references prepare a complete replacement history/graph before replacing the accepted list. Commit details and commit-file comparisons are also re-read without clearing their accepted snapshots first. Fully hiding or changing the workspace still releases detail/diff bodies.

Opening a new commit or file first prepares its snapshot while the accepted parent stays visible, then publishes the complete page without an intermediate loading screen. Back cancels a pending child; repeated clicks replace that pending destination rather than adding navigation levels. A commit's file drill-down keeps the root list and the parent commit's actual native scroll containers mounted, hidden and noninteractive. A staged-file drill-down also retains the commit message editor. Back exposes its accepted parent immediately while revalidating it, preserving the reading position and already loaded immutable row statistics. Selecting a commit highlights it without making that row the top of the returned history list.

The Changes list shows staged files first, followed by conflicts, unstaged changes and untracked files. Each row has comparison-specific addition/deletion counts and a separate stage/unstage button; pressing that button does not open the diff. These inline buttons are plain icons with no glass or background, retaining the shared icon control's hit target and disabled styling. The file-diff toolbar also stages or unstages that one file; a rename includes both its source and destination. The top menu provides explicit **Stage all changes** and **Unstage all changes**, independently of the current search/group filter. These operations update the index only. Unstaging on an unborn branch removes index entries without deleting working files. Conflicts and ongoing merge/rebase/cherry-pick/revert/bisect operations require a terminal; this panel never implicitly continues them. Known active or uncertain OMP work in any loaded chat using this worktree blocks staging and committing.

The **Changes** view selector includes total line additions/deletions using the review selector's shared styling. If a large count cannot fit beside the global actions, native label fitting uses the compact view icon and keeps the full total in its hover/accessibility text. Totals compare the actual working files against HEAD, including new files and native rename detection, independently of staging, filtering or scroll position. They do not add together overlapping staged/unstaged comparisons. A disposable index and object directory contain only the relevant HEAD entries and intent-to-add paths; repository data and hooks are untouched. Unborn branches compare against an empty index. File rows retain their individual HEAD → index, index → working tree or selected-parent comparison.

Native `--numstat -z` reads bypass external diff/textconv and preserve literal paths. Common row reads are batched; individual untracked/renamed reads have bounded concurrency. Verified counts remain visible while refreshing or staging. Unchanged HEAD, file metadata (including same-size edits), Git configuration and attribute inputs reuse the cached total; unchanged comparison/index inputs also reuse row counts. Staging refreshes the comparison counts while reusing the net total. Counts publish after revalidating their inputs, and late/cancelled results cannot replace newer ones. Binary contents have no text-line counts and are labelled in rows. An unavailable row comparison displays a dash; net totals can still be read independently when a conflict lacks index stage 2. An unavailable total also displays a dash. History detail counts load only for visible rows. Hiding the Git pane cancels counts and rejects late results.

**Commit staged changes** in the top ellipsis menu opens another drill-down level with the message and the reviewed staged-file list. File rows open their index diff and Back retains the draft in nonfullscreen. In fullscreen the composer occupies the right column, its file comparisons expand inline, and selecting a working-tree file in the left list replaces the right-hand detail while retaining the draft. The duplicate circle-check entry is removed from the toolbar. Global selectors, refresh and submission remain in the single top row, with batch operations in its menu; per-file stage/unstage buttons are beside their rows. The message input uses the shared noninteractive Liquid Glass input surface and performance-mode fallback as an explicit owner-requested exception for this multiline field. Its bottom-right corner holds the plain `light.beacon.max` generation icon, with no button background or explanatory line above it. While generating, an empty editor shows **Writing a message…** as a native placeholder, with no separate status line below. The placeholder never enters the draft; an existing draft remains visible and editable. At narrow widths the existing compact view/scope controls leave room for icon actions. Command-Return submits only when the current review is valid. The conversation toolbar's duplicate **Commit…** item and its stage-everything sheet are removed; that menu retains its separate Push, pull-request and repository-opening actions. Local commits have one entry point in the Git sidebar.

The review pins the branch/HEAD and a digest of complete index bytes (32 MiB maximum); unsupported or symlink indices remain browsable without write authorization. External staging or a branch change invalidates submission until an explicit refresh accepts the new review. Native Git works on a private index while the real worktree's `index.lock` excludes other Git writers; only the index is atomically published afterward. No working-file reset or checkout is involved, and later unstaged edits do not enter the commit. Linked worktrees use their own index and HEAD. Git's native identity, hooks and signing remain enabled. A hook that changes the reviewed commit tree or a failure to synchronize after HEAD advances is reported as an already-created commit requiring inspection; it is never automatically retried. This does not claim an atomic filesystem snapshot against noncooperating external tools or independently started OMP work.

Submission is local only and never pushes. The message is limited to 64 KiB without NUL, retained after failure or tab/settings/window hiding, and cleared only after a confirmed matching commit. Submitted writes finish independently of page visibility; read jobs, watchers and unsubmitted message generation still stop when hidden. An uncertain result keeps the draft and blocks further writes until the user explicitly opens **Review commit result**. Drafts and receipts are session memory, not a new disk journal. The input's optional generation button explicitly generates from the reviewed index patch through the existing configured OMP text-generation path, never on opening the editor. Late generated replies cannot replace typed edits or a changed/hidden review.

**Debug** observes the current main OMP conversation. Its compact status, current stop, selectable call stack, expandable scopes/variables and action history reuse the existing sidebar and source previews. Opening it never starts OMP or a debugger. A matching npm SDK/Bun host reads the same public `dapSessionManager` used by the native `debug` tool. Extension hooks capture direct and nested/eval debug calls; workers do not populate their parent's inspector. The first version has no launch, continue, pause, step, breakpoint editing or evaluation controls.

Debug history belongs to the chat and is stored as **runs → stops**. Every launch/attach has an independent run identity; adapter-created child sessions remain in the root run. The toolbar’s title selector reuses the Git branch menu and shows the viewed run. Run entries show only their title and ordinal on one line within a 360 pt menu; long titles use an ellipsis, with the full title available on hover and to accessibility. An explicit historical selection stays pinned when another run starts; **Latest debug run** resumes following new work. The status label describes the viewed run, uses the interface callout size (one step smaller than body) and has semantic colors. The compact detail toolbar groups step navigation in its ellipsis menu and retains the status color/accessible description and step counter. Historical browsing never starts OMP or sends DAP requests.

A visible paused inspector displays at most 64 frames, 32 scopes and 200 variables per expansion, with a 1,000-node / eight-level view budget and bounded strings. Successful stack, scope and variable reads are persisted into their exact run, stop and frame. Register scopes retain their adapter presentation hint; values and expanded register banks are captured through the same variables interface. Only values actually read are saved. There is no automatic traversal of all objects, threads or registers, and no process memory dump. OMP’s public variables API has no pagination; transport limits apply after the native scope response. Hidden tabs, folded sidebars, hidden windows and historical run selections cancel inspection. A nonfullscreen step detail also cancels live inspection while its overview is hidden. Native file, process, run, stop, frame and reference checks reject late results; persisted references are only data and never restore adapter authority.

The overview shows the live stop or the selected run’s last saved stop. Every activity step retains arguments/results/output and displays the stack, variables and registers known after that step; later reads cannot overwrite an earlier step. Saved values appear before the saved stack, allow expansion of captured children and show changed values as old → new when the previous step has a matching frame/scope/value. A new stop never inherits another stop’s variable references. Unread values remain absent. Empty sections are hidden and detail spacing follows the [UI convention](ui-guidelines.md#调试详情间距). Activity rows omit ordinals and time; rows without summaries use one line. A live activity list follows new steps until the reader scrolls manually. Returning to the bottom or choosing Latest resumes following. The native viewport stays mounted during detail visits to retain scroll position. Fullscreen keeps it visible beside the selected step and live inspection remains available. Run/step selection survives source-tab visits. Breakpoint activity uses dot.square. Source links use the debuggee cwd, preserve line/column navigation, and require a readable regular file. Across stop snapshots, call stacks and step details, these links reuse the Files tree’s cached Finder file-type icons. DAP source references, unavailable files and library-symbol pseudo paths remain inert. This version does not request adapter source/disassembly or expose arbitrary native thread/session selection.

Retention is bounded per chat: 32 runs, up to 128 activity steps and 64 stops per run, 128 captures and 128 KiB of capture payload per stop. A run has a 1 MiB combined detail/snapshot payload budget; all runs share 8 MiB. Individual tool details retain the 8 KiB input / 24 KiB result / 12 KiB text limits. Newer payloads are retained first; older payloads can be marked truncated, and the oldest run is removed when the run-count limit is exceeded. JSON metadata/escaping and OMP’s own journal are additional disk costs. A separate, process-local historical preparation cache remains bounded to 128 entries / 1 MiB.

Flat older GUI archives migrate launch boundaries into independent runs. Opening a run can recover its missing calls by exact native call ID in one public JSONL scan, bounded to 128 MiB, and persist recovered values into their original stops. Older stop-wide tool reads are replayed at their exact steps; sidebar reads without a saved step boundary are conservatively attached to that stop’s last recorded step. Terminal evidence also repairs older completed runs that were incorrectly marked interrupted as another launch began. Each actual launch remains a separate run even when it reuses the same program. Missing or ambiguous calls remain unavailable; similar actions never substitute for them. Recovery has no spinner or provisional generic DAP title. The model tool history and live inspector use the same literal snapshot representation, while raw custom DAP stack frames remain in their tool detail when their IDs differ from the native manager’s mapped frame IDs.

A live main-agent debug begin reveals the Debug tab in windows displaying that chat, including a folded sidebar. An explicitly selected historical run/step stays selected. Subsequent inspection calls respect the user’s tab choice; restored history and metadata alone do not trigger presentation. This UI intent is process-local and never restored from the archive.

While a debugger exists, a lightweight 750 ms native metadata sample observes asynchronous stop/exit changes and protects the OMP process from automatic GUI recycling, even with the panel hidden. These samples do not query the adapter or refresh its native idle timeout. The public manager has no event subscription; this is action/state visualization, not lossless instruction tracing. Without the SDK, extension tool results provide history only and the panel reports unavailable live inspection. OMP retains native timeout and debugger cleanup ownership.

**Session history** (会话记录, `point.bottomleft.forward.to.arrow.triangle.uturn.scurvepath`) retains the saved `trajectory` tab identity and reads the current native session plus explicitly known canonical Hydra descendants. The source selector reuses their existing identities and avatars; it never discovers unrelated sessions or launches OMP. Records follow the active native parent chain, including retained pre-compaction ancestors. The list actions menu switches between the default **Tree view** and **Flat view**. A native user entry starts one round; model requests, responses, final replies and context/configuration events stay within that round. Assistant tool blocks nest under their exact native response; tool results and starts retain the existing unambiguous call-ID merge. Pre-round or unanchored observations belong to **Session events**. Captured requests use their recorded dispatch leaf to locate the round, never a timestamp/model/text guess to attach them to a response.

Tree mode pages 20 complete roots at a time and pages each expanded branch independently in batches of 40 records, with at most 480 visible rows. It groups the complete indexed ancestry before applying filters or pagination, so an 80-record boundary cannot split a round. Flat mode retains 80 records per page. **Time: oldest first** and **Time: newest first** reorder tree roots only; children always retain chronological/native block order. Filters preserve and reveal matching records' ancestors without counting those ancestors as matches; filtered branches remain collapsible. Search scans bounded summaries, names and entry/call IDs, not unloaded tool bodies. Disclosure arrows change expansion independently of record selection. A collapsed ancestor subtly indicates a retained descendant selection. Refreshes preserve the reading anchor and manual expansion. Source, search, filters, view mode, sorting and root/flat paging remain in the topbar; per-branch continuation controls follow their subtree.

**Copy visible detail** includes only the bounded visible fragment. **Copy as JSON**, available in the detail actions menu and as a dedicated button in wide detail columns, instead copies the complete selected section/value, including undisplayed field and text pages. It preserves JSON types and uses indented JSON with sorted object keys. Credential and image/blob exclusions apply recursively. Export stays inside the existing source limits and additionally caps formatted output at 16 MiB, 500,000 values and 128 levels; exceeding a bound fails explicitly instead of copying truncated JSON. Copy shares the serial reader, keeps the displayed snapshot unchanged and is cancelled by navigation/hiding, so a late result cannot overwrite the clipboard for another selection. Empty containers and scalar values have no ineffective disclosure. Credential pins, known credential fields, provider replay payloads and image/blob bytes remain excluded at every expanded depth. Native timing, usage and status are shown only when recorded; missing results do not imply running work.

Native `custom` entries with `customType: tool_execution_start` are folded into the corresponding tool's **Tool execution started** detail section, matched by an unambiguous native call ID, tool name and ordering on the active branch. Repeated start markers remain independently inspectable within that section; their native entry identities stay in metadata. A start without a visible assistant call remains one observed tool row and can join its exact result, without presenting its projected arguments as full tool input. Ambiguous or malformed data stays inspectable rather than being guessed into another call.

Tool list captions select the operation's subject: bash commands; read/write/edit paths; search patterns and scope; eval titles or code; web queries; task names; questions; or the native action and target for structured tools. Mounted `write xd://` calls show their device and decoded subject. Execution options, nulls, replacement bodies and unrelated fields stay in full argument details. Dynamic MCP/extension tools use recognized subject fields or recorded intent, and leave the caption empty when neither is available. Captions remain bounded to 512 Unicode scalars. Thinking-level changes show the newly recorded level with the existing localized effort names; unknown native levels remain verbatim.

Every native assistant envelope appears once as a **Model response**, whether it contains prose, reasoning, tool calls or no content. Failed and cancelled replies retain their native status. The response owns its **Message**, **Thinking** and model metadata, including usage and timing. A model's text containing only one `.` (ignoring surrounding whitespace) is displayed as empty in both summaries and message details; the response, reasoning, tool calls and native journal stay intact. Other prose, user text and tool inputs/outputs retain literal dots. A response without message text opens its reasoning when available, otherwise its metadata. Tool rows follow the response in native block order and contain only their own input, execution starts, output, result and identifying metadata; they do not repeat the response's message, reasoning or model usage. Input remains the default tool detail. Counts, filters and paging include responses and tools once each. Selections and historical anchors targeting a merged execution-start entry resolve to its tool. Row icons align to the title's first baseline using its font metrics across Interface sizes, with a 1 pt optical descent.

The last assistant envelope in each native user-message round appears as **Model reply** (模型回复) with `ellipsis.message` when its native stop reason is `stop`, it contains visible prose and no tool calls. Earlier responses in a continued round, truncated/failed/cancelled responses, empty replies and unknown completion states retain **Model response**. This distinction is calculated on the complete active ancestry before paging or filtering; both labels remain in the **Model responses** type filter and share the same message/thinking/detail navigation.

Native `custom` entries with `customType: session_exit` appear as **Session exit** records. They are OMP lifecycle diagnostics: `kind: normal` with `reason: dispose` records a normally released session instance, which is visible when the history is next read. They are not new model replies. The native reason, recorded time and any pending-tool diagnostics remain inspectable in result details.

At sufficient width, fullscreen retains the history list beside its detail with the shared draggable divider. Summary rows use their natural one- or two-line count measured at the unsplit overview width with the current interface font. Opening or closing detail keeps that count and its native line height; a one-line summary truncates at the narrower width without adding an empty second line. Actual window or font-size changes recalculate the count. Title-only rows retain their compact height. The current chat remembers selection, filters, sorting, reading position and the separate history column fraction across sidebar visits; normal sidebar mode uses Back navigation. Only the visible history source owns a coalesced file/directory watch and one serial read. Hidden pages keep bounded displayed records/details but release the index and watchers. The reader accepts only regular `.jsonl` files inside this edition's `omp/sessions` folder, caps a journal at 64 MiB, complete lines at 8 MiB and entries/projected records at 50,000, and defers incomplete tails. File replacement, truncation and same-size rewrites invalidate offsets. Session-header identity and generation checks reject stale selections and late results. Files beyond those limits show a recoverable error; full-history trees, external profiles and payload reconstruction are not imported.

Selecting a record opens its message, thinking, tool input/output, result details or native metadata through the detail-section menu. Text uses the original 16,384-scalar pager. Switching modes stays in the current section and restores each mode's address/page when available. In tree mode, objects and arrays show field names, type/count summaries and native disclosures. Expanding inserts children immediately below the parent; ancestors and simultaneously open sibling branches remain visible. Long strings expand in place into read-only, selectable native text readers with a 240 pt height cap, wrapping and independent vertical scrolling. Sibling updates preserve those readers, text selections and scroll positions. Short values remain inline. Each field page contains 40 values; independent previous/next controls follow that branch's visible subtree. Paging keeps a bounded window, so values beyond the total rendering budget remain accessible without loading preceding pages. Text pages contain at most 16,384 Unicode scalars and use paging controls within that value. One detail has a shared limit of 400 field rows, 64 expanded branches, 65,536 expanded text scalars and 16 logical levels. Limit messages request collapsing another branch rather than silently reading an entire payload. Detail indentation uses 14 pt steps up to 56 pt in wide columns and 12 pt steps up to 36 pt in narrow columns; deeper values retain a level marker and expose their full path on hover. No path banner is added above the fields when expanding or collapsing. Expanded rows have no surrounding tint; only the text value uses the same quiet 10 pt rounded surface and content inset as chat tool details. Connector elbows and disclosures share title anchors and gutter coordinates.

Tree detail actions include **Expand all parameters** and **Collapse parameter branches**. Expand-all recursively opens the current detail page and the selected pages of its branches within the existing 64-branch, 400-field, 65,536-text-scalar and 16-level limits. It does not read undisplayed pages or enable a permanent auto-expansion policy. The accepted expanded paths become ordinary branch state, so subsequent manual collapses stay closed on refresh. Collapse, detail-mode/source/record changes and hiding the pane cancel pending bulk expansion; late results cannot overwrite the newer choice.

The first detail is revealed only after its complete snapshot is ready. Pending record or detail-mode changes retain the accepted snapshot and section/copy controls at their normal opacity. Hit testing and live identity checks block stale actions without toggling those controls through disabled glass/text appearances. Expansions, branch paging and unchanged refreshes preserve the outer detail viewport; changing the selected record, detail mode, section or root detail page resets that viewport. Superseded reads cannot commit into a different selection/source. Expansion, branch pages and selection survive sidebar visits and view-mode switches, with bounded navigation caches for four sources and twelve record/section detail scopes per source. Fullscreen history uses resizable columns at 720 pt or wider (280 pt overview / 360 pt detail minima); smaller fullscreen widths use the same list-to-detail navigation as the ordinary sidebar.

Enhanced request capture starts with future requests from GUI-launched OMP SDK sessions, including the inherited extension in native child sessions. It does not backfill earlier requests. The public native registry supplies session identity; the public agent stream supplies a separate request ID, context, allowed options, the payload returned by native hooks, response metadata, final output, usage and timing. Payload revisions and responses remain under that exact request scope. Context is the agent-stream input; payload is the provider callback value after extension modification, not a promise of byte-for-byte HTTP or WebSocket traffic. Provider-internal retries can expose multiple payload/response observations without exposing every wire attempt.

`Request context.tools` contains tools available to the model, including declarations such as `read` even if the model never calls them. Actual invocations appear as tool-call records and in the request output's tool-call blocks; an available tool declaration is not execution evidence.

Public side-turn and maintenance operation boundaries also capture their result/error; a failed boundary is retained even when it produced no provider callback, while a successful local operation without provider evidence is not treated as a request. Side-turn context is read from the native context builder. Remaining helper calls that expose only session-bound provider callbacks appear as **Provider payload** or **Provider response** observations. These are not joined using timestamps, models, message text or reused abort signals. **Observed** means the public interface supplied an observation without a model completion result. Completed, failed and cancelled states use native result/error evidence; unfinished records whose owning process or capture heartbeat has ended show **Interrupted**. Request sections use the same detail navigation, paging, copy and fullscreen columns, with no extra explanation rows.

Capture sidecars live under this edition's `omp/requests/`, keyed by the native journal's canonical path, header ID and leaf at dispatch. Only requests anchored to the active ancestry appear. Files use private permissions and atomic replacement; payload reads reject symlinks and changed files. Captures redact credential fields, authorization values, provider signatures/replay data and image bytes, and store only allowed options and response headers. They still contain conversation text and tool schemas. Capture metadata reports redaction and truncation. Empty request options are omitted, so provider observations open their payload or response section instead of an empty options page. Each section is bounded to 1 MiB, options to 64 KiB, payload-revision history to eight 32 KiB snapshots, responses to 32 snapshots of 8 KiB, and each document to 5 MiB. There are at most 16 active captures and 32 coalesced pending writes. Retention keeps up to 512 requests / 64 MiB of documents per session, 8,192 requests / 512 MiB globally, and 30 days. Old documents are pruned by the writer; no native journal is deleted. A capture directory with more than 2,048 summary entries is truncated with a warning; unrelated documents and temporary files do not consume that limit. A capture failure marker is named by the failed session's canonical path, is cleared by that session's next successful write, and expires after 24 hours even if no writer runs; it marks only that session's history, not other conversations or process-level diagnostics. The reader reuses parsed summaries while the session's capture summaries and their metadata are unchanged, re-evaluates running leases on every read, and reuses the selected document until that document changes. Page and detail navigation therefore do not re-parse every sidecar. Save/read failures for a session appear in that session's history topbar action menu; recording failures do not change inference results. The visible pane watches capture revisions as well as the native journal and releases both watches when hidden.

**Browser** uses the embedded Chromium panel described in the [browser guide](browser.md). The context ring retains its management controls; the OMP side-question popover stays beside the composer.

Switching to a panel or the picker cancels pending file opens and releases the active file reader and watcher. The current conversation’s Files page stays mounted while its tab exists, preserving expanded folders, the hidden-file policy, directory and native scroll position across file-preview, picker and other panel visits. Hidden Files pages cancel directory reads and cannot receive input; returning revalidates the root listing without clearing existing rows. Closing the Files tab, changing conversation, or tearing down the sidebar releases that mounted page. Folder expansion and the hidden-file policy remain small in-memory conversation state; the tree’s scroll position is not written to the preview journal. Returning to a file restores its reading state. File links and drops activate their file tab, including when the picker is open. Settings, window hiding and sidebar folding preserve tab state while suspending visible-only work.

Attachment image and video popovers fit their media inside 600 × 450 pt, with a 624 pt content width. Their media uses the shared window corner radius (16 pt) with continuous rounding. Before opening, the panel measures the fixed media slot and its localized footer together, keeping the same 12 pt padding above the media and below the file information/actions without resizing after presentation.

Each image popover presentation explicitly starts its own image load through the bounded thumbnail cache; measurement and SwiftUI appearance do not start or own that request. Closing or switching the popover cancels its consumer, and late results cannot replace a newer presentation. Missing or undecodable images show **Unable to preview image** with **Retry**, rather than leaving the loading indicator active. Reopening or retrying starts a fresh consumer and can reuse a successful cached decode.

Every file click retains its own tab; subsequent files do not replace earlier ones. Reopening the same canonical file activates its existing tab. Old temporary tabs migrate to retained tabs. Tabs can be closed, reordered, or closed together. Tab titles and file icons follow the Interface body size; close icons use the smaller caption size while following the Interface size setting. Workspace browsing loads one folder at a time; filename search starts only after a typed, debounced query. Search excludes hidden and generated folders, with a clear message. The folder browser can explicitly show hidden/ignored entries, and Finder is available for results beyond the limits.

New conversations and legacy empty-preview state default to the workspace tree. Startup waits for saved tabs before choosing the tree, so an existing selected file or panel restores normally. Closing a selected tab activates a remaining tab; closing the final sidebar tab shows the panel picker. The top-bar external-file button uses `plus.square.on.square`.

Both the file reader and the complete chat host (timeline, composer and floating panels) adopt their destination width once while native outer viewports slide and clip them. Left-sidebar open/close projects the detail pane's final width from the window layout, keeping both native content hosts fixed through that motion too; manual divider/window resizing follows the actual viewport. The timeline no longer applies a second predicted sidebar delta. Closing captures a bounded viewport image before releasing the live reader and watcher; the image is discarded when the motion ends or the window/context changes. Rapid reversal continues from the current width, and a collapsed pane reserves no divider width. Selected-tab highlighting and scrolling use the existing Chrome motion; initial restoration and pane resizing keep tab scrolling immediate.

Opening files or folders uses no application loading spinner or placeholder artwork. Opens run through a queue with at most four concurrent filesystem jobs. ## Renderers and scope

Text files, Markdown source and diff text (including line numbers) use the exact **Code** point size from Appearance. Rendered Markdown uses the exact **Interface** size for body text, code, tables and footnotes; headings retain their relative hierarchy. These sizes update in place when settings change, preserving source selection and document identity, independently of the **Content** size.

The chat and file pane share one continuous, theme-tinted surface over the window backdrop. The browser, Markdown/WebKit canvas (including over-scroll), source viewport and line-number gutter, image margins/transparent pixels and PDF margins leave that surface visible. The window's transparency setting, wallpaper, performance mode and native accessibility fallback therefore apply to both panes together; individual readers do not add another glass panel. Code blocks, tables and search controls retain their own readability surfaces. PDF pages, image pixels and video frames keep their original content. Quick Look and AVKit remain native embedded views: their outer host uses the shared backdrop, while a system preview generator or player may supply an opaque document/video canvas that the public embedding API does not let the app recolor.

Both terminal locations use a clear default SwiftTerm background and no extra panel fill, exposing the same window backdrop and its transparency/solid fallback. Default text adapts to light/dark appearance and caret/selection follow the theme accent. Foreground text, the view itself and explicitly colored ANSI cell backgrounds keep their own opacity; terminal applications that paint an explicit background can still cover the backdrop.

The PDF host clears PDFKit's native scroll and clip backgrounds after document layout, including replacement scroll views. This keeps page gaps and the top/bottom rubber-band areas on the shared backdrop in both appearances. Background-induced tiling finishes before the host applies the floating controls' bottom clearance; PDF pages retain their own paper and content.

The existing macOS `WKWebView` host needs WebKit's undocumented `drawsBackground` KVC switch in addition to transparent CSS and the public `underPageBackgroundColor`; WebKit tracks the missing public setter in [issue 221663](https://bugs.webkit.org/show_bug.cgi?id=221663). The host probes the native setter before using it. If a future WebKit removes it, Markdown falls back to an appearance-resolved opaque document/over-scroll background rather than throwing an unknown-key exception; other readers and the shared pane surface stay unchanged. Offscreen checks verify actual light/dark Markdown canvas and PDF margin/page-gap/over-scroll pixels as well as native source/image transparency. Quick Look generator content and final window glass composition still require manual acceptance.

## Files, state and resources

Local references support absolute paths, `file://`, `~/`, relative paths, `:line[:column]`, legacy `:start-end`, and `#Lline`/column/range fragments. Existing literal filenames win over delimiter conventions; percent escaping is decoded once for link references. URLs are standardized and symlinks resolved for tab identity. Local reads preserve their source conversation directory, OMP's canonical result paths, and grouped targets. A removed worker worktree yields a missing-file view, with no fallback to the main checkout's same-named file. Diff current-file actions account for repository roots above a project's working subfolder.

Each window retains only the selected visible reader and its file watcher. The watcher observes the file and parent (or closest surviving ancestor), supports atomic replacement/deletion/recreation, filters unchanged sibling events, and releases its descriptors on stop. Refresh also invalidates native renderer versions, including explicit refresh of a document package whose inner content did not change its container metadata. Deep package descendants do not have recursive watchers.

The source reader retains one native TextKit layout stack. Its document is clipped to the scroll viewport, keeping horizontally scrolled source outside the fixed, transparent line-number gutter. Noncontiguous layout keeps reflow local to requested ranges; whole-document idle layout is disabled, and unchanged wrapping/ruler policies do not repeat native geometry setup. Strict native UTF-8 decoding and byte-buffer line indexing reduce first-frame work while preserving BOM UTF-16/32, control-character validation and Unicode/CRLF navigation. Toggling wrapping preserves complete source, selection and horizontal access without retaining a second layout cache.

The browser’s remount cache keeps only the most recently listed folder’s bounded metadata, scoped to its workspace, path and hidden-file policy. The retained Files page also holds its already loaded expanded-folder rows, subject to the existing per-folder listing cap; it reads no additional folders while hidden. Those rows can appear immediately when the browser is reopened; every opening still performs a fresh background listing. Changed paths never display another folder's rows, and read failures or workspace changes discard the cached listing. Filename queries remain debounced and are not cached as a workspace index. Images publish a small native frame before their final decode; clarity upgrades retain the same original coordinates, zoom and scroll position, and cancellation prevents stale pixels from reaching a newer file.

Inactive tabs keep small source/document selection and scroll positions, PDF page/destination/scale, image scale/position and media time. Quick Look's opaque display state stays in memory only. The bounded state journal is `file-previews.json` in the edition's existing `OMP GUI Native` / `OMP GUI Native Dev` library, with debounced writes and termination flushing. Capture runs use their separate storage. Sessions are keyed by conversation plus execution directory; closed, minimized or hidden windows suspend readers and resume them when shown.

Explicit limits:

- Complete source: 2 MiB, accepting UTF-8 and BOM-marked UTF-16/32. Oversized, invalid, binary, missing or unreadable sources have a localized explanation and retry/external-open actions.
- Rendered Markdown: at most 2 MiB and 20,000 lines; larger documents use complete source with an explanation. There is no image/formula count cutoff. Highlighting is bounded to 64 KiB per code block. MathJax limits TeX buffers to 16 KiB and macro expansion to 1,000. Local raster files are limited to 64 MiB; image metadata is requested six at a time and reserves layout before pixels load near the viewport. Static, unrotated PNG/JPEG files at most 4 MiB and 2,048 pixels on each edge pass through as compressed bytes for WebKit decoding; other inline images keep the bounded native thumbnail/PNG path. No additional image cache is retained.
- Source syntax colors: first 262,144 UTF-16 units and at most 20,000 spans. Remaining text is still complete, selectable and searchable.
- Decoded image pixels: a standalone image's first frame has a longest edge of at most 768, followed by a final preview of at most 3,072; inline images are limited to 2,048. Small images decode once. Accessibility reports original dimensions, and the floating zoom meter reports actual preview resolution in its tooltip.
- Closing viewport snapshot: longest edge at most 2,048, at most 16 MiB of RGBA pixels per transitioning window; cleared after completion, context change, resize, hide or teardown.
- PDF find: at most 500 matches; callback gating and query generations prevent unbounded queued work or stale results.
- Folder list: 2,000 returned entries / 20,000 scanned entries. Workspace search: 20,000 scanned entries / 1,000 matches. Incomplete results are disclosed, with Finder as an outlet.
- Tabs: no count limit, at most 24 retained sessions; inactive documents/pixels/players are not cached. State restore reads at most 4 MiB. At most four pending filesystem resolutions execute concurrently; queued work is fenced against later close, navigation, browser and context actions.
- File Diff: at most 4 MiB of patch output with a 15-second command deadline; larger patches show a limit message rather than a truncated comparison. Existing 1 MiB / 20,000-line deferred parsing and lazy diff rendering remain in force.

Quick Look/PDFKit/AVKit have their own native resource behavior; these limits bound application-controlled source, decoding and callback work rather than promise a fixed RSS for every possible document. Native decoding calls already in progress may finish after cancellation, but their results cannot replace a newer reader.
