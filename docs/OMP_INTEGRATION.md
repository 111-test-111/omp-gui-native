# OMP native integration

Current implementation reference. Dated protocol research and acceptance are in the [archive](archive/README.md); [status](status.md) separates historical evidence from current capability and unfinished acceptance.

## Native ownership and launch

OMP owns model providers, authentication, model roles, tools, MCP, extensions, skills, native workers, isolation and applying results. The GUI hosts public CLI/RPC/SDK surfaces and projects their facts. It has no second runtime adapter, worker scheduler, MCP hub or model API client.

[OMPSession](../OMPGUI/Services/Providers/OMPSession.swift) starts one native process per active lead conversation, in that conversation's execution directory:

- `--mode rpc-ui --no-title --session-dir <edition-library>/omp/sessions`.
- `--resume <sessionFile>` when restoring native identity.
- Optional `--model` and `--thinking` only when selected; otherwise OMP defaults/roles remain authoritative.
- Native approval mode: supervised → `always-ask`, auto-accept edits → `write`, full access → `yolo`; `OMP default` passes no override.
- A private watched `--config` overlay for the Hydra delegation preference and native `providers.openaiLiveSteering: false`, plus a per-session `--extension` for GUI guidance and bounded file-write observations. OMP consumes additional messages at native tool boundaries; ordinary WebSocket streaming remains available. The override is inherited by native workers and does not write the active profile.

The active native OMP profile stays external. Changing the binary/environment/session signature can replace the process; changing only Hydra's delegation preference updates the overlay without stopping workers.

## Transport, capability and settlement

[OMPRPC](../OMPGUI/Services/Providers/OMPRPC.swift) matches both request ID and command, handles timeout/cancellation/exit and publishes per-process [capability evidence](../OMPGUI/Core/Models/OMPCapabilities.swift). Successful replies prove support; an exact unknown-command failure proves unsupported; other failures/timeouts remain unknown. Harmless empty worker-control probes cannot address a worker. A version or slash-command catalog alone never enables a control.

[StdioProcess](../OMPGUI/Core/Support/StdioProcess.swift) decodes logical JSON frames on its read path. Protocol-v2 chunk reassembly is bounded to 64 MiB and 1,024 chunks; invalid order, duplicate starts, inconsistent length and nested chunks fail. The decoded output backlog is limited to 256 MiB. Preserve these bounds and [PendingReplies](../OMPGUI/Core/Support/PendingReplies.swift) generation guards when changing transport.

After protocol negotiation, the session requests `set_event_filter` with `events: null` and `messageUpdates: "delta"`. Only a successful current-process response echoing `messageUpdates: "delta"` confirms the projection; older OMP versions may accept the command while ignoring that field. Rejection, timeout or missing echo leaves the GUI on its compatible full-update contract. The decoder accepts either shape throughout the connection and still consumes complete `message_end` frames and protocol-v2 chunks. All event types remain enabled; the GUI adds no event allowlist or extra polling.

Prompt admission, input consumption, `prompt_result`, `agent_end` and `session_settled` have different meanings. [OMPActivity](../OMPGUI/Core/Models/OMPActivity.swift) retains dialogs, queues, compaction, retries and background work before authorizing idle recycling. On older SDKs that count deferred next-turn context as queued work, SDK-confirmed idle stops the busy indication while retaining the queue protection. OMP 18.13.3 excludes untriggered hidden next-turn context from its runnable queue and reports native settlement; the GUI accepts that public contract. Both automatic and manual compaction lifecycle events protect native maintenance, fence stale state reads and update the context result.

## CLI discovery, models and settings

The Models settings page and composer catalogue contain chat models only. Native judgment models such as Jev belong to the separate `judge` role and are deliberately excluded from the chat picker; their absence here does not establish that OMP lacks them.

Provider sign-in lists combine the public `get_login_providers` inventory with the installed SDK's public authentication policies. Only authorization-code, device-code and audited browser-capable custom flows receive **Login** / **Sign in again**. API-key-only providers such as TypeSafe appear in **Edit model configuration**, including when they have a console URL. OpenRouter retains both browser authorization and key editing: its browser flow returning a durable API key does not make it key-paste-only. Image backend actions use the same policy. Unknown policies or an installation without readable policy metadata never gain a guessed login button; the native terminal remains available.

Configured providers group login aliases only when OMP's public authentication policy declares the same `storeAs` credential namespace. In OMP 18.12.5, `openai-codex-device` (headless/device) stores as `openai-codex`; both RPC login entries check that same key source, so two authenticated entries do not establish two separate subscriptions. The GUI shows one configured row, prefers its canonical browser action where available, and retains the actual alias action if it is the only supported route. Native login/logout identities and account reports remain intact. Names alone never merge providers; missing policy metadata leaves identities distinct. This is presentation grouping with no credential read, deletion or migration. Both Codex routes use the shared OpenAI logo; unknown brands use a same-size uppercase name initial.

Logo assignment is separate from authentication grouping. One bundled [explicit brand manifest](../OMPGUI/Resources/ProviderLogos.json) is shared by model selection, configured/login providers and key editing. Public model catalog, provider entries and authentication policies are audited together, so distinct IDs such as `zai`, `zai-coding-plan` and `zhipu-coding-plan` display the same reviewed logo while keeping their native identities and credentials. The [fixed 18.12.5 audit](evaluations/2026-10-26-provider-brand-audit/native-identities.json) covers 99 IDs and records deliberate initial fallbacks. No endpoint, display-name, model-name or credential-namespace heuristic assigns a brand.

The same resource supplies reviewed display-name fallbacks when native discovery returns only an ID. `minimax-cn` is presented as **MiniMax (China)**, distinct from international MiniMax and both Token Plans. Key editing additionally reads the public catalog's `getBundledProviders()` so model-only providers without auth policies are not omitted; known structured/OAuth policy restrictions remain. China and international overrides are written to their exact `models.yml` provider IDs and resolved independently by OMP. Names never alias one region's key to another. Key search matches IDs, readable/localized names and declared environment-key names, including multiword queries. OpenRouter intentionally uses an enlarged uppercase O rather than its bundled retained logo.

Provider **Login** / **Sign in again** and image-backend login start OMP's public `login` RPC and automatically open its validated `open_url` destination in the default browser. OMP's loopback launch URL takes precedence when supplied; unsafe links are rejected and duplicate destinations do not open additional tabs. There is no OAuth sheet. [Inline controls](../OMPGUI/App/Views/Settings/OMPLoginControls.swift) show a cancellable browser-wait status in Providers. Native instructions, including device codes, and requested code/redirect-URL inputs are available under the initially collapsed **Additional sign-in steps**. Failed browser launches expose Open / Copy actions. A successful native reply removes these controls and refreshes credentials and model discovery. Leaving the Providers page cancels its unfinished login.

Device codes are entered on the provider's website; paste-code flows need the code or redirect URL returned to OMP. Required native input automatically expands **Additional sign-in steps**, while instructions alone stay collapsed. The initiating provider's button becomes **Cancel** while authentication is pending, so cancellation remains accessible without reaching the supplementary controls. Current OMP RPC rejects secret input and prompts required before the first auth URL. Known custom flows requiring these steps (GitHub Copilot's initial host prompt, Perplexity, Snowflake, Alibaba endpoint/key setup, Cloudflare token/account setup and Xiaomi key paste) are excluded from browser sign-in. They retain native terminal configuration and, where the provider accepts an ordinary key, the key editor. A supported flow that fails still offers **Continue in OMP terminal**. Credentials, callback listeners and persistence remain in [OMP's login RPC](../OMPGUI/Services/Providers/OMPNativeLogin.swift).

Configured providers also have **Sign out** beside **Sign in again**. The action immediately uses OMP's public `get_logout_accounts` and `logout` RPCs to remove every currently listed stored credential for the selected provider, including aliases resolved by OMP. It does not ask for confirmation or show a success popup. After removal, refreshed native authentication removes the provider from Configured providers; credentials/model discovery and image credential indicators are refreshed. Login, duplicate logout and credential editing are blocked while the mutation runs. Errors, including partial multi-account failures, stay inline and refresh the confirmed native state rather than hiding an authenticated provider. Environment/config keys are not deleted: OMP's `remainingSource`, or a missing stored-account inventory, explains why authentication still applies. Credential contents never cross into the GUI, and other providers' stored accounts remain untouched.

Settings → Providers → **Edit model configuration** opens a bounded, searchable [API key popover](../OMPGUI/App/Views/Settings/OMPModelConfigurationPopover.swift) anchored to that button. Each row contains the provider name, a masked input without placeholder text, and an independent reveal/hide button. Closing the popover discards revealed state. The list scrolls with its indicators hidden to avoid covering inputs; search and key fields use a contrasting neutral Liquid Glass tint that adapts to light/dark appearance and retains the performance fallback. The header's file icon opens the native configuration in the external editor; its path and credential metadata are not displayed. [Its native helper](../OMPGUI/Resources/OMPModelConfiguration.js) derives key-capable providers from the installed OMP SDK's public auth and environment-key registry, adding existing custom providers. Pure OAuth aliases and structured OAuth credential formats are not presented as ordinary API keys. This editor requires the npm SDK installation and Bun; standalone installations retain the settings page's native configuration-folder entry.

The popover initially masks values and edits only `providers.<id>.apiKey` in the active profile's `models.yml` (or existing `models.yaml`). A legacy `models.json` is read without migration and saved to `models.yml` only on Save. Literal keys, environment-variable names and native `!command` references are retained without resolving them. Existing OAuth accounts stay in OMP's credential store: an explicit key overrides OAuth for the same provider, while emptying the input removes only that override and restores OMP's normal credential selection. Separate provider ids keep their separate native auth semantics.

Save validates with OMP's schema, preserves other provider/model/top-level fields, normalizes YAML formatting (including removal of comments), detects external edits/profile changes, and atomically replaces the destination with mode `0600`. No-change saves do not rewrite the file. Key values cross a private stdin pipe, stay only in the presented editor's memory and the native file, and are never placed in argv, GUI preferences or discovery caches. Saving refreshes settings/model discovery; existing sessions retain OMP's own reload behavior. Saving does not prove the key is accepted by a service. The main provider list still reflects OMP's login inventory, rather than every custom API-key definition.

Settings → Providers → **Image generation and editing** exposes OMP's independent **Enable image generation and editing** switch when the installed native config CLI declares `generate_image.enabled`. This setting defaults to false in OMP 18.11.2: a preferred image model and valid credentials alone do not register the tool. The switch writes that native setting through the existing guarded config CLI. Native long-lived RPC sessions watch configuration files and reconcile the tool registry; GUI launch arguments do not restrict the tool list. With `tools.xdev` enabled, the model discovers the tool through `read xd://` / `read xd://generate_image` and invokes it through `write xd://generate_image`; otherwise it appears as a directly callable tool. Project settings and explicit native tool restrictions retain precedence. Changing activation sends no image request.

The [native image catalogue](../OMPGUI/Services/Providers/OMPImageConfiguration.swift) lists backends and image models, including those without credentials. The [settings section](../OMPGUI/App/Views/Settings/OMPImageSettingsSection.swift) places both native selectors at the row's trailing edge, with no manual reload button or footer explanation. It saves an exact `provider/model` selector to `modelRoles.image` through the existing native config CLI, preserving every other role. Automatic removes only that override; unresolved existing selectors are displayed rather than silently replaced. OMP's `generate_image` handles generation and edits through the same role. Native fallback chains, conversation-provider choices, per-request model overrides and existing-session reload rules remain authoritative.

Image credentials are shared with Providers: stored OAuth, stored/configured API keys, environment keys and command-backed references follow OMP's native auth cascade. A green check reports native credential presence; keyless endpoints are identified separately. It does not certify token freshness, subscription entitlement, hosted-carrier availability or service acceptance. Missing credentials show the native login and/or a provider-filtered key editor; OAuth-only aliases keep their own login identity. Discovery uses the offline SDK catalogue and `hasConfiguredAuth`, never resolving model key commands, refreshing OAuth or sending an image request. Credential-store failures remain errors rather than being reported as signed out. Only names, selectors and presence metadata cross to this settings view. Opening the page, returning to the app, and completing login/key edits refresh the state. This section requires the npm SDK and Bun; native model configuration remains available for other installations.

Settings → Models retains the public `omp models --json` catalogue's declared `input`, `contextWindow`, `maxTokens`, four `cost` components and `pricingStatus` as optional [model metadata](../OMPGUI/Core/Models/ModelMetadata.swift). Clicking a row opens a bounded read-only [detail popover](../OMPGUI/App/Views/Settings/ModelDetailsPopover.swift), using the already loaded catalogue without a model request or new discovery process. Missing metadata stays unknown; explicit free and plan-included statuses remain distinct from unknown all-zero cards. Session RPC catalogue updates can refine capability fields while preserving the CLI's resolved base-price snapshot. The displayed catalogue prices are base rates; the GUI does not duplicate OMP's pricing engine or claim these rates are a bill. The `input` list describes declared model modalities, not a guarantee that a compatibility transport forwards every modality.

Settings → Skills uses [OMPNativeSkills](../OMPGUI/Services/Providers/OMPNativeSkills.swift) to call the public `omp skill list <temporary-directory> --json` with the active profile environment and without chat-only configuration overlays. Discovery runs independently of the selected conversation; only explicit `provider:user` sources with a local `SKILL.md` enter the list. OMP retains source opt-ins, exclusions, plugin discovery and name resolution. Unsupported CLI versions report their native error rather than falling back to a GUI filesystem scan. No session, model request, install or configuration write is issued.

The skill list places refresh at the header's far right and limits descriptions to two lines. Clicking anywhere on a skill row opens a 580 × 540 popover anchored to that row, initially in rendered Preview. Its source button matches the file sidebar: the code icon stays fixed, becomes selected in Source and toggles back to Preview when clicked again. Source keeps lines unwrapped and supports native vertical and horizontal scrolling. Source switching, refresh and Open containing folder share one toolbar capsule; Close stays separate. The folder action opens the listed SKILL.md's parent directory in Finder. The [skill viewer](../OMPGUI/App/Views/Settings/SkillsSettingsPage.swift) reuses the existing bounded, read-only file loader and Markdown/source renderers, including the 2 MiB complete-source limit. Preview and Source retain their own reading positions; refresh rereads the file and keeps the displayed content until a result arrives. Closing the popover releases its document. Refreshing the inventory, switching profile context or leaving the page closes the preview; no skill content is stored in GUI preferences.

[Fast model controls](../OMPGUI/App/Views/Composer/EffortSlider.swift) use the native `set_fast_mode` action. Compact CLI model discovery is supplemented by one read-only `get_available_models` RPC with `--no-session`, preserving the CLI's thinking-level list while reading native API/identity/service-tier facts for Fast. No mutating capability probe or model-name heuristic is used. Only an explicit Fast click may start or resume the conversation connection; opening the popover only refreshes an already-active one. A selected replacement model is synchronized only while the native session is settled, with session/model/revision fences and the selected effort retained. No prompt is sent. Native configuration written before the first prompt keeps its session-file identity.

[Session run options](../OMPGUI/Services/Providers/OMPSession+RunOptions.swift) retain the underlying `set_fast_mode`, `set_auto_retry`, `abort_retry`, `set_slow_mode` and `set_cache_warming` adapters. The context popover no longer exposes a run-options section or retry/Slow/warming controls. Fast confirmation requires native `enabled`; `active` is tracked separately and stays unknown when absent. The bolt reads confirmed request state; only matching current-model `fastModeActive: true` enables accelerated track motion. No local model preference stands in for native active state.

Timed-out controls retain request identity and block automatic recycling without manufacturing a primary assistant turn. A matching late response or process teardown resolves that protection; no automatic replay or profile write is added by the Fast control. Existing retry/Slow/warming projection and native ownership remain unchanged. Their previous UI and acceptance evidence are historical; see the [current workflow](chat-workflows.md#fast-模式).

## Subscription usage and voice boundaries

The GUI's Usage settings page accounts for OMP turns saved by this edition. Provider subscription quotas and monetary balances are separate: Settings → Providers → Configured providers reads public `omp usage --json` through [OMPProviderUsageReader](../OMPGUI/Services/Providers/OMPProviderUsageReader.swift). Configured rows combine native available-model providers, authenticated login providers and confirmed usage accounts, so API-key providers such as DeepSeek are included. Each row shows only its quota amounts and known future reset/replenishment time, or available monetary balance; grant/top-up details, duplicate headings, meters and update timestamps are omitted. Multiple accounts retain supplied account labels. Refresh uses the page's existing top control. The model picker only groups and selects native models, with no usage reads or display. The inherited `PlanLimitsReader` remains disabled; credentials stay with OMP.

Only explicit, finite native values with a valid report time are eligible for display. Missing/unsupported values, unknown statuses, explicitly estimated/OMP-observed sources, reports older than ten minutes and limits whose reset time has passed are omitted rather than rendered as zero or unknown placeholders. Native zero and overage values are retained. Unit balances are not invented percentages; normalization follows OMP's `resolveUsedFraction`. Incremental `tick`/`regen` windows are labeled as replenishment rather than a full reset, and unfamiliar reset meanings are hidden. [The projection](../OMPGUI/Core/Models/OMPProviderUsage.swift) bounds output to 128 reports, 128 limits per report and 1,024 total limits; subprocess output is capped at 3 MiB and 45 seconds. No raw response or credential is saved by the GUI.

Visible provider settings hold shared read leases and a memory-only cache: a successful read is reused for 60 seconds, with a ten-second failed-read retry throttle. Each entry/refresh resolves public `omp config path` in the native profile environment, and a successful usage read checks it again before publication. Executable, environment, profile and catalog changes reject old results. Leaving the last settings view cancels the usage subprocess; there is no hidden polling or chat startup. A local thirty-second display clock only hides expired values; it does not fetch. Extension discovery stays native so extension usage sources remain available. OMP continues to own account selection, endpoint access, credential refresh and native cache/persistence. See the [interaction guide](chat-workflows.md#聊天模型选择与套餐用量) and [delivery evidence](archive/provider-logos-deepseek-coverage-2026-10-26.md).

DeepSeek balances supplement the native reports through [OMPProviderUsage.js](../OMPGUI/Resources/OMPProviderUsage.js). With an npm SDK and Bun, the existing native configuration helper loads OMP's model registry and provider extensions, checks endpoint ownership, and resolves the selected DeepSeek key through the public `AuthStorage.keys.get` cascade. This covers `models.yml` overrides as well as stored and environment credentials; OMP 18.12.5's usage collector alone does not consistently consult config-only keys. Without that SDK path, the CLI receives the bundled read-only `--extension`, using the credentials its native usage collector supplies. This fallback does not add support for config-only keys that OMP itself omits. Unsupported helpers or credentials leave the balance absent while ordinary native reports remain available.

Only the official HTTPS `api.deepseek.com` endpoint is eligible; custom relay base URLs do not trigger an official balance request. The read uses `GET /user/balance`, rejects redirects, bounds the response to 64 KiB and ten seconds, and never forwards keys or raw error bodies to Swift. Native extensions are loaded before resolving the key so their endpoint/key overrides remain authoritative. Exact decimal strings for CNY/USD total, grant and top-up balances cross a versioned metadata projection, separate from native percentage/credit units. Missing fields, unsupported currencies, conflicting currency rows, failure and stale results stay hidden; no sum or currency conversion is inferred. There is no new credential store, global extension installation or profile write. The dated [coverage and implementation record](archive/provider-logos-deepseek-coverage-2026-10-26.md) lists all 22 built-in usage ids and further official API candidates.

OMP also has native live-voice controls in the inspected installation; no GUI voice entry point is enabled. Capability discovery, native audio/account availability and a process lease would be required before exposing a call. See the dated [usage, voice and optimization assessment](archive/upstream-functional-stage2-2026-10-26.md) for the inspected version, source evidence and remaining acceptance. Local [draft dictation](chat-workflows.md#本地听写) uses macOS Speech independently and never creates an OMP model request.

## Prompts and file-write observations

[OMPSystemPrompt](../OMPGUI/Services/Providers/OMPSystemPrompt.swift) edits native shared-config `APPEND_SYSTEM.md`, preserving UTF-8, symlinks and external-change checks. It does not pass `--append-system-prompt`, so OMP retains file discovery and project precedence. A public `before_agent_start` hook appends the [built-in guidance](anti-slop.md) to the existing system blocks without accumulating duplicates.

[OMPFileSnapshots.js](../OMPGUI/Resources/OMPFileSnapshots.js) observes awaited native `tool_call` / `tool_result` hooks for local `write`. An RPC start notification is too late to serve as a before-write barrier. It attaches before/after text under `details.ompGUI.fileSnapshot`; native diffs take precedence. Each native session, including workers, has an independent map.

Reads are limited to 1,000,000 bytes per file and pending baseline text to 8,000,000 bytes. Successful writes advance the baseline for later prepared writes to the same file. Binary/unreadable/oversized text remains unavailable, and failed/virtual writes do not fabricate a successful snapshot.

## Hydra and file context

[OMPSession+Subagents](../OMPGUI/Services/Providers/OMPSession+Subagents.swift) uses process-level `set_subagent_subscription(progress)` for lifecycle/summary updates. Only visible detail consumers acquire leases and read `get_subagent_messages(sessionFile, fromByte)`; byte cursors advance after a complete batch. Closing one view does not stop another visible consumer. No hidden transcript polling is added.

Visible `irc:incoming` custom messages project their structured instruction body as timeline input, for both top-level journal entries and nested custom-role messages. A new instruction after a native stop starts the next displayed round; in-flight instructions stay in the current round. Lifecycle completion updates worker status immediately but never closes a partially read transcript. A completion arriving during a read requires a further journal read before any fallback turn end, including aborted work without a final assistant message.

Native worker IDs may be reused. Observation identity, session file and spawning tool call fence progress, delayed history, results and controls. Unknown model/effort/workspace/isolation/application values stay unknown. Cancel acceptance requires `cancelled: true`, but final state still comes from native lifecycle. Steering preserves drafts until native acceptance.

Hydra on adds `task.eager: preferred`; off inherits native policy. Leaving a pair restores native worker defaults. The original floating panel and report/steps popovers remain; there is no task workbench or separate brief form. Ordinary chat input reaches OMP through the shared prompt/follow-up path. OMP alone schedules workers, manages isolation and applies results.

[Preview host tools](../OMPGUI/Services/Providers/OMPSession+HostTools.swift) register `gui_read_selected_context` and `gui_open_file_location` only after successful `set_host_tools`. The former returns explicitly shared context; the latter validates paths against the source worktree, including symlinks. Native call/cancel/result identity suppresses late replies. This is not an MCP server.

## Side questions and disposal

[OMPSideQuestionController](../OMPGUI/Services/Providers/OMPSideQuestionController.swift) sends public `btw` and `btw_cancel` requests. It reduces `btw_record`/`btw_delta` independently of the lead decoder and fences a topic by the connection, native record ID and request identity. Started records may precede the admission response; terminal snapshots correct deltas and cannot regress to an older running admission record. Unknown admission retains its request ID and never resends. Optional support is learned from this process's actual response, without a history probe.

[The display model](../OMPGUI/Core/Models/OMPSideQuestion.swift) retains one topic, at most 16 turns and 64 KiB of cumulative question/answer display text. Full record projection and native-byte accounting run off the main actor; native records are not copied into GUI storage. Follow-up admission stops at 16 turns or 1 MiB of cumulative native question/answer bytes. Inputs above 128 KiB are rejected. Deltas coalesce over 50 ms; closed popovers release their hosting content and add no history reads, workers or polling. `get_btw_history` is deliberately unused.

A terminal record is emitted before the asynchronous checkpoint and is not a durability ACK. `notice` frames with `source: btw-history` remain attached to the side question. Active/unknown side work blocks recycling without changing the lead's replying phase. Terminal answers retain a separate persistence blocker. Automatic recycling uses [OMPRPC.beginDrain](../OMPGUI/Services/Providers/OMPRPC.swift): close stdin, keep consuming output and wait for actual native disposal/exit. It rejects new requests and never escalates to SIGTERM on a timer. A known save failure prevents this automatic drain and ordinary connection replacement. Errors received during disposal survive even an exit status of zero; they do not become a successful save claim. Explicit Stop retains its existing termination behavior.

There is no across-connection BTW recovery, raw sidecar access, topic browser, GUI persistence or independent cost calculation. A native EOF disposal failure can only be reported; the protocol provides no successful terminal-checkpoint event or bounded history read with which to repair it.

## MCP, history and context

Settings lives in the main window. The MCP page adapts Tivano's curated catalog and reuses its approved icons. Presets are organized into five groups: Development tools, Browser & web, Collaboration & business, Cloud & databases, and Knowledge & reasoning. Brave Search, Tavily, Exa, Perplexity, Filesystem, Fetch, Memory and DeepWiki are no longer offered as presets; existing native profile definitions remain editable. Connect opens a button-anchored template form; it saves an ordinary definition to the active OMP profile. Existing definitions keep the native editor and enable/disable/remove controls. Catalog templates preserve literal environment references, omit unset optional authorization headers, and never start local packages or claim a live connection.

Connection/sign-in forms and recognized catalog servers' authorization popovers show every tool name recorded in the preset, using the cards' typography with a bounded scroll viewport instead of the three-tool preview. These are catalog examples, not live server discovery. The forms use the existing native window-coordinate presenter so opening or dismissing them does not ask the Settings scroll view to reveal a focus anchor.

OAuth catalog entries offer Add and sign in, and configured OAuth servers have a Sign in with OMP action. [The login host](../OMPGUI/Resources/OMPMCPLogin.js) invokes the installed OMP npm SDK's public MCP discovery, `MCPOAuthFlow` and native credential APIs. OMP owns PKCE, the callback listener, dynamic registration, tokens and refresh material. Swift receives only native credential references, with original-byte/profile checks before saving the auth definition. Sign-in starts only on that user action and is cancelled when its popover/page closes or profile identity changes. Browser failure retains the authorization URL and native manual callback input. No model session, MCP manager, GUI credential database or proxy is created. This optional action requires an npm SDK with the relevant exports and Bun; unsupported installations can use OMP's `/mcp reauth` command instead.

[OMPMCPConfiguration](../OMPGUI/Services/MCP/OMPMCPConfiguration.swift) resolves the active profile with the public `omp config path` CLI, stripping chat-only overlays. Settings → MCP lists and searches only that profile's `mcp.json`; it never discovers or edits project MCP files. Install server uses one transport selector for stdio, streaming HTTP and SSE. All local processes share the command/argv form; enter `npx`, `uvx` or another executable directly. New servers start with stdio and a blank command; no separate installation-method selector or package-position validation remains. Installation saves a native definition: OMP starts it in new sessions, and its configured npx/uvx command downloads a package when needed. Install server and each server's Edit button open visual forms anchored to their respective buttons. Popover titles use the interface body size. Local arguments and environment variables, and remote HTTP headers, begin with one blank editable row when empty; npx has no preset `-y` argument. Untouched automatic rows are omitted on save, existing empty argv entries are preserved, partial unnamed values are rejected, and named empty environment/header values remain valid. The scrolling form reserves horizontal drawing space for glass edges while keeping its vertical viewport bounded. Enable/disable respects native denylist precedence; rename migrates matching overrides, and removal clears that definition and its overrides after confirmation. OAuth, native secret references and unknown fields survive form edits without resolution. Cancel discards the editor.

The page and server popovers offer Open JSON file, which opens the active profile's `mcp.json` in the system's default application. No embedded JSON editor remains. Missing files are created as a private native empty configuration only when Open JSON file is requested; existing malformed or oversized regular files can be opened without parsing or rewriting them. Symbolic links and nonregular files are rejected. The interface-font profile path and install/open-file actions sit above one shared shaded card. Server rows and the centred empty state use that same card; the transport picker aligns to the trailing edge. Editors show field labels and validation errors without repeated paths or explanatory paragraphs.

AppModel owns one in-memory MCP profile cache, warmed from the main window after the login environment is available. Page visits immediately reuse its installed list while profile identity is checked in the background, retaining loaded controls without a refresh placeholder. One debounced app-owned file watch keeps that cache current across page navigation, covering in-place writes, atomic replacements, deletion and recreation without polling or another CLI process for each file event. Returning to the page and application activation re-resolve the native profile; executable/environment changes discard the previous identity's cache immediately. Visual saves update the shared list immediately; refresh requests received during an operation drain afterward. The page has no refresh button. Reloading the list preserves an open form's original snapshot, so an external edit still rejects that form's stale save. Leaving the page closes its forms but retains the bounded shared cache/watch; application termination stops both. The first read after launch still requires the native profile lookup if prewarming has not completed.

GUI reads and saves are bounded to 2 MiB; visual collections allow 128 entries each and larger definitions use the external file action. Save rechecks executable/environment identity, the native profile path, resolved directory and original bytes, rejects symlink/nonregular files, and cooperates with OMP's macOS advisory lock before replacing the file atomically with mode `0600`. Unchanged saves preserve original bytes. Conflicts retain the draft and require reopening rather than overwriting external edits. No native config or credentials enter GUI preferences. OMP owns discovery, transports, OAuth and servers. Catalog forms link to their documentation and token-creation pages; there is no terminal-launch action. Enabled configuration or successful sign-in does not prove connection, and the page does not collect live connection observations.

Normal chat persistence, native message-edit `branch`, attachment restoration, inline tools and Usage context controls remain. [Context requests](../OMPGUI/Services/Providers/OMPSession+Context.swift) expose stats, custom compaction, session auto-compaction, handoff and HTML export. Timed-out mutations remain unknown/in flight until their matching late reply or teardown; a settled snapshot does not authorize repeating them.

The context ring remains available for ordinary OMP conversations before any usage report. A session-file-bound native display snapshot is persisted with the GUI document and survives connection recycling; it restores no in-flight command, compaction or unknown-outcome state. Saved values are labelled until refreshed. Visible existing conversations prefetch on entry and after native work settles through the normal runtime startup path without sending the composer draft; a new empty chat does not start OMP merely for prefetch. Usage reuses a completed context read until the native revision changes, while explicit Refresh always reads again. Concurrent cold callers share startup. Occupancy is published after state, statistics after their response, and handoff history when ready, keeping existing values visible throughout. Handoff history is read on connection and after a native context rewrite rather than again after ordinary messages. Old conversations without a cache still require their first native read. A missing native journal fails inspection instead of falling back to a new empty session. Existing live connections are reused without changing their launch configuration, and read-only context refresh remains available during ordinary model work. During a pending context mutation, refresh keeps the current snapshot instead of queuing a short-deadline read behind native serial maintenance; a mutation waits for an already admitted context read. Native workers are never restarted for inspection. Compaction, handoff, export and automatic-compaction changes retain their existing native-idle and confirmation guards.

Native workers use OMP progress `contextTokens` and `contextWindow`, never cumulative `tokens`. Their read-only Usage surface can also recover the latest response usage from the bounded, complete-line journal's active parent chain; a missing capacity uses only the reported worker model's loaded catalogue metadata. Compaction invalidates earlier response occupancy. These are last-reported response sizes, which can exclude pending input and later tool results, rather than a replacement for OMP's live context tokenizer. Worker refresh shares concurrent reads, rejects changed observation/file/progress identities, and does not launch a process, replay the timeline or expose lead-session management/statistics controls.

Manual handoff commits its document as a native `compaction` entry with `method: "handoff"`; the public RPC reply supplies only an optional `savedPath`, not the document body. Normal and late replies retain the result in the session snapshot rather than popover-local state. Usage exposes a selectable, bounded document disclosure, copy and explicit Markdown save; it does not invent a path when native handoff created no separate file. Explicit failure or null results remain distinct from older successful history, and a missing document read never turns a confirmed mutation into failure.

Session history uses the bounded, read-only journal and capture readers described in [workspace panels](file-preview.md). Independent fork, the tool inspector, MCP startup observation and runtime diagnostics are not exposed. RPC plan-mode entry/exit is not exposed. The [tool catalog](OMP_TOOLS.md) describes exact native tool identity, not a promise that every tool is enabled.

## Context inspector data

The workspace [Context pane](../OMPGUI/App/Preview/ContextWorkspacePane.swift) distinguishes three independent measurements:

- **Current occupancy:** [OMPContextControl.js](../OMPGUI/Resources/OMPContextControl.js) reads the public SDK `getContextBreakdown()` and `agent.tokenizer` in the existing native process. OMP supplies provider-anchored/local occupancy plus system prompt, system context (project files and appended instructions), skills, active tool schemas and messages. The registered private extension command is intercepted before prompt admission, including while streaming, and does not append a message. Ordinary RPC `get_state.contextUsage` remains the fallback when this optional SDK interface is unavailable; no detailed categories are invented from it.
- **Request composition:** [OMPContextComposition.js](../OMPGUI/Resources/OMPContextComposition.js) measures the transformed `agent.streamFn` context before capture redaction/clipping, using OMP's tokenizer. Categories cover system blocks, tool declarations, user/assistant text, visible reasoning, tool calls/results, images, summaries, custom content, shell/Python output, unmatched request additions/edits and remaining framing/opaque content. Converted content and timestamps must match exactly, with duplicates consumed once, before historical provenance is assigned. System-context/skill subdivision is supplied only by OMP's native occupancy breakdown. Category estimates sum to their own total; provider-reported input (fresh + cache read + cache write), its difference from that estimate, and observation of a final payload callback remain separate facts. Provider serialization/extensions can change the final request. Side/compaction/title calls never replace the latest agent request.
- **Recorded cumulative accounting:** [OMPContextInspectionReader](../OMPGUI/Services/Providers/OMPContextInspectionReader.swift) reads only this edition's bounded native journal. All retained branches count, including native `model_usage`, compatible legacy usage entries and outer task usage reports; worker files are not recursively summed. Reasoning is a reported subset of output, never added again, and cache-hit rate excludes generated output. Missing counters/cost remain unknown. OMP 18.12.5's `get_session_stats` covers its active context window and is therefore not used as a lifetime total. Deleted/rotated journal content and unsaved in-flight usage cannot be recovered.

Request composition and reported counters persist in bounded capture summaries, independently of request documents. The reader validates the native session identity and current leaf ancestry, excludes off-branch/leaf-less captures, and tracks summary revisions even when usage is unchanged. It never re-estimates clipped/redacted bodies. Metadata limits retain eight names per category, preserve omitted-name tokens and explicitly flag incomplete composition. Native journals remain limited to 64 MiB / 50,000 entries; capture retention remains the existing 30-day/count/byte policy.

Detailed latest-request usage requires summaries written by the context-aware capture runtime. An already-running OMP process can continue writing the earlier summary format after the GUI updates: its full request document may contain usage while the Context summary lacks those counters and payload-observation evidence. New native sessions write the complete summary. The Context pane does not backfill earlier summaries from request documents; those fields remain unavailable for such captures.

Payload observation has three states: a captured boolean supplies explicit yes/no; a missing, null or invalid field is unknown (`—` in the pane/Markdown and `null` in JSON). The [shared occupancy selector](../OMPGUI/App/Preview/ContextWorkspaceStore.swift) keeps the pane and reports consistent. For archived chats, idle native workers and disconnected idle cached sessions, a freshly accepted, revision-validated journal takes precedence over runtime caches. Active workers retain their live progress usage. A compaction or model change that invalidates journal usage stays unknown rather than falling back to an older cached count.

OMP allocates a native session path before lazily creating its journal at the first assistant message. Before a non-archived chat has a finished turn or an accepted journal snapshot, a missing/empty journal or incomplete first header is a quiet pending state. Existing live context remains available and the next normal refresh can accept saved data; no zero usage or successful saved-read timestamp is invented. Lost retained journals, access failures, corrupt complete lines and paths outside this edition's session folder remain errors. Session-reader errors use their localized descriptions.

The visible [store](../OMPGUI/App/Preview/ContextWorkspaceStore.swift) polls at five-second intervals only while the selected conversation is running or has native work (including compaction or queued/background work). On the transition to idle it replaces an automatic read with one final refresh, or queues that refresh behind an initial/manual read, then leaves periodic polling stopped. The final refresh may reuse a live connection but never resumes a stopped OMP process. Repeated idle notifications do not trigger further reads. Panel/workspace/window hiding or teardown cancels polling and reads, including a pending final refresh. Idle entry reads saved metadata only; a manual click may explicitly refresh an existing ordinary session. Manual busy state is independent of automatic/final reads, and an explicit click during initial cache loading or a completion read is followed by one complete manual refresh. File/generation/cancellation fences reject late results. Errors retain the prior snapshot with its last successful refresh time. Archived chats and native workers use saved responses with a clear pending-content limitation; active or manually refreshed existing ordinary chats may establish a read-only connection without submitting a draft. No settings, credential or native active-profile write is performed.

The original 18.12.5 public SDK source was compared with [upstream RPC](https://github.com/can1357/oh-my-pi/blob/main/docs/rpc.md) and [SDK documentation](https://github.com/can1357/oh-my-pi/blob/main/docs/sdk.md), and with pi-app's `context-detail.ts`, `context-composition.ts` and `ContextDetailPane.tsx`. OMP adds native provider-anchor and five-way occupancy information beyond the request/accounting separation in that reference. Tokenizer/category estimates still do not certify exact provider wire-token counts. See [verification](verification.md) for the scoped deterministic checks and remaining GUI acceptance boundary.

## Native Mnemopi memory

Settings → Memory is an explicit GUI opt-in, off by default even when the external profile selects a memory backend. [OMPMemoryConfiguration](../OMPGUI/Core/Models/OMPMemory.swift) stores only launch preferences: automatic recall/retention, embedding language and the approximate context budget. The shared `memory` model role and advanced native provider/database settings remain owned by OMP. No memory content is copied into GUI preferences.

Every GUI RPC launch, including account/model discovery, receives a private `memory.backend: off` overlay, removed after the native process exits. The watched conversation overlay also retains that neutral startup value. An enabled npm SDK host uses the published settings, Mnemopi scope and session-state exports in [OMPMemoryControl.js](../OMPGUI/Resources/OMPMemoryControl.js), then waits for the native memory transition. It composes OMP's own `per-project-tagged` bank scope from the canonical Git common directory, installs the native session state and refreshes the native base prompt before admitting user input. Independent clones have different common directories; non-Git folders use their canonical working directory. Git errors do not silently select a different bank. Native workers inherit the parent's memory state through OMP. These exports and Bun are required when enabled; missing support fails startup before sending a user prompt. Disabled chat keeps the ordinary CLI/older SDK path.

OMP still builds the memory instructions, retrieves first-turn `<memories>` blocks, persists/reuses `memory_recall` snapshots, reports changed recalled facts, supplies compaction context and owns all memory tools, extraction and database handles. The GUI extension appends its existing guidance to the native prompt array. Repository identity replaces the default cwd-derived project bank; existing cwd banks are not migrated or deleted. A newly enabled connection seeds the native retention cursor at the existing user-turn count, so conversations written while off are not retrospectively retained.

Changing any memory preference is allowed only after every known conversation, queue, dialog, worker, side question and native operation is idle. The app blocks new connections, saves GUI snapshots, sends EOF to existing native connections and awaits actual disposal/exit. It persists the new preference only after every drain succeeds. A failing or explicitly interrupted drain leaves the preference unchanged; no timer escalates the change into SIGTERM. The next explicit request restores the conversation with a freshly constructed tool registry and prompt. Disabling keeps native databases and historical transcript text, but starts no memory backend and adds no memory tools/guidance.

OMP's automatic retention saves completed user/assistant turns with source `coding-agent-transcript`; explicit retain tool writes use `coding-agent-retain`. Native recall can include both original dialogue and individual facts in its `<memories>` block. `buildDeveloperInstructions` combines the native memory guidance with its cached recall snippet, which explains why the previous settings prompt display could look like a conversation. This native retention/recall behavior remains unchanged.

The viewer uses a process/session/request-correlated extension command over normal RPC UI. Opening Settings → Memory automatically discovers the native memory files when memory is enabled and a conversation is selected. The app keeps only global shared file metadata in a bounded, in-memory cache for the current conversation/configuration; reopening the page reuses it and concurrent openings share a pending read. The list has no refresh button. A small spinner directly beside the Memory files title marks initial discovery and stops when files, an empty result or an error arrives. The runtime continues to use project plus global memory, including repository/worktree sharing.

Global files are available for project chats and independent tasks alike. Native startup prepares an application's task working directory even before its first user prompt, including discovery and cold preview requests. This does not send the draft, cross the first-turn persistence boundary or create a project record; missing user-owned project directories are not recreated. Normal first-send directory preparation still precedes the persisted first-turn boundary.

Preview opens from its own button as a fixed-size popover containing the read-only native file reader, a refresh button and a close control. Refresh reloads the current file while preserving the displayed content and reader state until the reply arrives. It displays entry content, source and date, with no search field. File/path identities must match the current native scope. A fixed, read-only SELECT through the public Mnemopi SDK `db` handle lists recent working, episodic and fact entries from that file; records include saved historical entries. SQL limits rows and content before returning them. Previews return up to 50 entries, capped at 8 KiB per entry and 64 KiB of content overall; this bounded preview may omit or shorten entries. Reading never replaces `lastRecallSnippet` or the persisted `memory_recall` prompt snapshot. The viewer issues no mutating SQL, dumps no native status and constructs no prompt text; storage, retention and injection remain OMP-owned.

Initial discovery, opening Preview or refreshing its content may start/resume the native connection; these reads send no chat message and do not poll. Switching conversations or changing memory configuration immediately invalidates cached metadata and closes the preview. Closing settings closes its preview while preserving the file cache. In-flight reads finish under native recycling guards and stale replies cannot refill a different context. Memory contents are not cached on disk. Native automatic memory work may still use the configured providers.

## Native goals

[OMPSession+Goal](../OMPGUI/Services/Providers/OMPSession+Goal.swift) uses the public `goal` command with `get/create/resume/pause/drop`. The on-demand `get` is read-only; a valid matching reply confirms process support. [OMPGoal](../OMPGUI/Core/Models/OMPGoal.swift) separately retains native state, pending mutation identity and explicit terminal evidence. `get_state.goal` and `goal_updated` cannot turn a missing/invalid field or null into a completed goal.

OMP owns the goal tool set, accounting, persistence and continuation. Automatic RPC continuation must be enabled by native configuration; the GUI sends no loop prompts and creates no scheduler. Native token usage includes new input, cache writes and output, excluding cache reads. A budget-limited goal may exceed its budget while a request wraps up; pause/drop do not abort that request. User abort pauses an active native goal. RPC exposes no budget edit, manual completion or atomic expected-goal-ID control. A spent paused goal cannot be resumed through the GUI; it must be dropped and recreated with a new budget and zero initial usage. Every mutation re-reads the singleton and checks its expected identity locally; a mismatched response is reported without retry. The read/apply race still requires native atomic support to eliminate.

The local `/goal` composer command selects Goal mode; its submitted body is the native objective. The toolbar entry is shown for this mode, a current goal or explicitly observed completion. Completion remains visible until another goal or native session replaces it; no second goal history is stored. The [anchored popover](../OMPGUI/App/Views/Chat/OMPGoalButton.swift) and [runtime bridge](../OMPGUI/App/Runtime/ThreadRuntime+OMPGoal.swift) do not start a process just to display state. An explicit objective submission may start/resume the connection. Both creation and an explicit resume may offer one ordinary user prompt only if the connection was and remains natively settled, its goal/connection identity is unchanged and no run has started meanwhile. Native work already scheduled or started wins, including a turn that already finished. A resume fallback sends the localized request to continue the current goal through normal admission/history. There is no automatic replay after an unknown outcome or a late confirmation. Mutation timeouts retain their request and recycling guard until a matching late reply or teardown. These control waits do not fabricate a streaming main reply. Goal submissions are limited to 128 KiB; observed goal text is retained for display up to 64 KiB, with UTF-8 boundaries preserved.

Unknown status/mode strings are retained as read-only observations with an update notice; invalid identities or counters are still rejected. `timeUsedSeconds` accepts finite nonnegative numbers, including fractional seconds. Usage shows the last native accounting report rather than an estimated timer. A wall-clock-only flush can emit `goal_updated` even without transcript persistence. The exact `goal.enabled` rejection records disabled policy separately from command support; it hides composer suggestions and blocks repeated mutations. A successful empty `get` does not clear that policy observation. Reconnecting creates fresh process evidence.

## Debug observation

The [debug bridge](../OMPGUI/Resources/OMPDebugControl.js) adds main-agent `tool_call` / `tool_result` hooks and the private `/omp-gui-debug` command to the existing native extension. The SDK host imports OMP's public `dap` export in the same process as `DebugTool`; it does not start another adapter, inspect private fields or replace tool execution. An actual hello acknowledgement confirms live inspection. The command is hidden from the composer and consumed before chat/event projection.

The only inspection operations are stack, scopes and variables, plus protocol hello and cancellation of an inspection read. References must have been returned for the current native conversation, DAP session and observed stop generation. Execution-changing tool calls invalidate that generation even when execution returns to the same line. One bounded adapter read runs at a time, with a five-second timeout and pre/post identity checks. Panel cancellation aborts only its read; it never pauses or terminates the debuggee. No expression evaluation or arbitrary DAP request is exposed.

Process-level metadata observations remain active while native DAP sessions or debug calls exist, preventing GUI recycling without displaying the agent as busy. Live variable references stay in the mounted inspector. Tool observations additionally retain bounded literal arguments, structured results and output (8/24/12 KiB per field group, 128 records and a 1 MiB detail budget) in the GUI conversation archive; historical values never authorize adapter reads. The selected older step may recover details by exact native call ID from the public OMP session JSONL, without invoking OMP.
