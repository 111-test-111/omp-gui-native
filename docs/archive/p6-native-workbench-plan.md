## 目标与边界

让用户更直接地使用 OMP 的原生交互、任务和 worker 能力。新页面使用 SwiftUI，必要处使用 AppKit，复用 Chrome、Hydra、系统材质、语义颜色和字体。现有 Markdown 文件预览保留 WebKit 并单独计量，不新增网页功能页面。

OMP 拥有模型、认证、队列、MCP、技能、扩展、子代理、隔离和结果应用。GUI 只呈现原生事实、编辑未提交输入并关联原生身份，不建设执行队列、任务调度器或 MCP hub。只面向新会话，不安排旧会话扫描、迁移、回填或自动导入。

本阶段不开发 OMP 命令相关功能，包括命令目录/面板、斜杠命令、参数补全、终端或 TUI 工作流及其包装入口。已有相关功能维持现状。下文的 RPC/SDK 方法是原生数据和操作接口，不扩展成命令入口；缺少公开接口的能力明确留空或延期。

复用 P1–P5 已有的发送、聊天记录、配置、扩展对话框和 Hydra。支持依据是当前进程的实际响应：18.3.2 的 worker stop/steer 保持不可用；18.11.1 已有实际调用证据。新接口候选在实现前确认参数、响应和取消语义，版本号不构成能力证据。

## P6.1 会话等待标签与原地交互

待处理收件箱及其面板、入口和最近请求缓存已移除。当前未查看的会话收到批准或提问时，在侧栏条目右端显示「等待批准」或「等待回答」；打开该会话后通过原有表单回复。项目、活动、搜索及子会话列表保持一致，悬停操作可用。

每个会话自行保存活跃请求和草稿，继续绑定请求实例、进程 generation 和原生会话身份。确认 transport 写入才清除已提交输入；未知送达保留输入且不重发。取消、超时或进程退出撤销请求及标签，不再维护跨会话聚合或最近请求档案。

完成条件：同时提问不串答，切换会话不丢活跃输入；标签随查看与原生请求状态更新，原有批准及问答交互可用。中英文文案保持一致，批准与回答分别使用琥珀色/紫色液态玻璃胶囊，保留性能及减少透明度回退；原生 confirm 使用独立审批卡片。详见[实施说明](p6-implementation.md#p61-会话等待标签--conversation-waiting-labels)。

## P6.2 Hydra 原生任务工作台

在现有 Hydra 上增加任务总览与详情：父会话、worker、实际模型和 effort、工作目录、隔离状态、进度、原生报告、文件及产物。原生缺失信息显示未知。

“新任务”编辑完整简报、文件上下文和预期结果，复用主会话原生提交路径，由 OMP 决定执行和委派。GUI 不制造 worker、不安排并发。提交后使用已支持的原生 steering、follow-up 和停止操作。

stop/steer 同时校验能力与 worker 身份；请求接受不等于任务结束，以原生生命周期确认结果。应用隔离结果只接已确认的 OMP 公开 RPC/SDK 接口；没有该接口时仅展示原生状态与产物，结果应用延期。

完成条件：父子日志和 tool call 可追溯，ID 复用不串任务，后台工作不被回收；隐藏详情不持续读取全文，重开按原生游标补读；实际 worker 的追加、停止和结果定位闭环可用。复用已有 P4/P5 检查。

## 性能和资源门槛

沿用目标：输入/菜单/按钮 p95 ≤ 100 ms，缓存会话可读首屏 ≤ 150 ms，万条记录冷首屏 ≤ 800 ms，本地流式事件至显示 ≤ 100 ms，空闲 GUI 平均 CPU ≤ 单核 1%。布局结束和主线程心跳不代替屏幕呈现测量。

重复操作沿用 100 次切换、20 次预览开关、稳定 30 秒后，内存增量 ≤ max(基线 10%, 20 MiB)。新功能只在影响这些路径时复测。分项记录 GUI、OMP、MCP 和 WebKit 的 physical footprint、抽样峰值及进程数，归属或读取失败保持未知。

各模块实现前写明缓存与订阅预算：按字节限制正文缓存、合并同类查询、不可见详情停止额外工作、只保留可见 Markdown reader。保持 Core → Services/UI → App，大帧、历史和重处理在后台，生产默认不开持续采样。

P5 的屏幕 p95、父版本对照、新版 WebKit 操作期间覆盖，以及大输出/多 worker/大文档峰值范围，归入阶段交付门槛，不阻塞独立功能实现。睡眠/唤醒、VoiceOver、输入法和系统减少动态效果待 owner 安排现场验收后关闭，不擅自改变系统设置。

## 验证规则与停止条件

遵守 [项目验证规范](../../AGENTS.md#verification-scope-and-stopping-rules)及[统一验证入口](../verification.md)。不默认运行全套检查或双版本完整矩阵。

1. 开始前确定最小验证范围，复用已有证据。文档、工具和版本改动仅做相关静态检查；代码改动做一次增量构建及对应检查，通过即停。
2. 失败先仔细阅读生产源码和测试代码、分析原因，修正实现或测试；不以反复重跑或新增测试代替分析。修复后只复跑受影响的失败项。
3. 仅在协议适配或原生版本变化涉及相关风险时，选择必要版本和接口各验一次。性能比较只针对变化路径，保留一次同负载基线与候选测量；条件不足时记录待验收。
4. P6.5 不加功能，不重复验已通过门槛。未通过项明确修复、延后或限制发布范围，不宣称全面通过。

每项功能在独立 worktree 开发，一个提交、版本递增和 Unreleased 记录；按仓库规则集成本地 main，保留 worktree。构建不启动 GUI，运行及系统操作遵守 owner 授权。本方案不包含远端推送、打包安装或发布。
