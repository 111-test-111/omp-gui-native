## 首次运行与失败分析

一次选择既有 `tests/acceptance/runtime.py --p5-forward --language zh-Hans`，使用已验证 Dev `0.1.60` / build `61`、官方 OMP 18.11.2、全新 GUI 库/defaults/native profile 和本地 MCP 素材。测量阶段没有模型请求。原始输出在 N4 worktree 的 `build.noindex/omp-p5-live/20261017-012036-639b8b38/`。

该次运行完成了万条消息数据、100 次聊天切换、20 次预览开关以及前后各 30 秒稳定、60 秒空闲采样，随后进入人工检查。人工检查超过 `OMPPerformanceRun` 固定的 600 × 500 ms 检查窗口，未及时创建 `finish`；检查按源码报 `Inspection must be explicitly completed`，自行退出。整轮状态是 **failed**，不是一次通过的系统验收。原因是人工完成标记超时，不是所测 UI/OMP 崩溃；不重跑已结束的历史/预览负载来覆盖该失败。

检查源码确认原生 RPC 独立于选中聊天 runtime，故后续在该隔离项目中新建真实 lead，通过仅监听 `127.0.0.1` 的确定性 provider 检查新入口。该动作发生在资源测量之后的 inspection 阶段，不把这段流式活动混入前后空闲比较。只退出本次 GUI 与其原生进程；既有用户实例未操作。

## 真实连接的局部窗口检查

在上述 inspection 的真实 lead 中观察到：

- Goal 的中文多行输入、Return 换行、Escape、草稿保留及 composer 焦点归还；2048 token 预算创建后显示原生状态，暂停/恢复/放弃均确认并显示明确终态。TextEditor 中 Tab 遵循原生文本行为，插入制表符；未把它当成已验证的完整键盘导航或真实输入法组合。
- 主回复按 80 段、每段 0.25 秒持续流式；旁问在主请求开始 9.37 秒后发起，得到独立回答。同主题追问、取消、关闭后草稿保留均可用；主聊天没有投递旁问文本。该本地 provider 共收到 5 个请求，包含原生标题请求，没有使用外部账号。
- Usage 的请求/实际 Fast 状态分别显示；不支持模型的启用被拒绝，随后停用清掉面板旧错误。自动重试停用 override、Slow 不支持提示、预热关闭回显以及滚动到底部的三个预热动作均可达。检查了当前实际窗口截图；未更改全局 Slow 或触发付费 warming。

发现 `Refresh` 与无预算的 `Not set` 缺失精确 catalog key。按本地化约定补为「刷新」「未设置」，Dev 推进到 `0.1.61` / build `62`。为只复核受影响窗口，增加独立 DEBUG 手动验收入口，复用真实 `ThreadRuntime` / `OMPSession` 和本地确定性 provider，不再强制执行旧历史/预览负载。

## 定向复核

本次编译变更一次 `make build` 通过，工具变更通过 `static:harness syntax`。新[手动入口](../../tests/acceptance/README.md)只自动通过生产 runtime 发送一条 `Q_BOOTSTRAP`，随后等待人工动作及 `finish`；它不自动判定文字/次数，不注入 activity，也不执行历史负载。原生边界清除继承的 OMP/PI 覆盖，使用隔离 HOME/profile 和本地 provider。

首次定向启动的实际界面显示父 worktree 的改动。阅读源码确认临时工作区只有目录、没有 Git 边界，Git 向上发现父仓库；通过本次 `abort` 退出并记为 failed。修正 launcher，创建独立 scratch Git 仓库并核对 `rev-parse --show-toplevel` 后，只重跑受影响的定向启动与 Python 语法检查。应用源码/资源未再变化，复用刚通过的构建，不为 fixture 修正重新构建。
