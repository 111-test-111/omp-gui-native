# 全局共享记忆预览卡死修复

2026-10-21，Apple Silicon / macOS 27.2。Owner 在本任务中明确授权启动、退出和重启任务 worktree 的 Dev 调试实例。该授权仅属于本次诊断与复核。

## 复现与原因

Dev 0.1.151 / build 152 在设置 → 记忆 → 全局共享记忆 → 预览中复现整个应用无响应。当前库只有少量短条目；接近预览上限的中文离屏布局未能复现实际显示周期中的卡死。

对本任务启动的实例采样，主线程持续停留在 `NSTextView.drawRect`、`NSLayoutManager` 的字形/高度计算、`NSClipView` 的文档尺寸反馈及 `PreviewTextHost.tile` 链路。原实现先让 AppKit 应用覆盖行号栏的 clip frame，再在 `tile()` 返回前收窄视口；绘制时两个宽度不断使 TextKit 布局失效。

新增回归检查直接观察未改尺寸的阅读器重复 `tile()` 时的视口 frame 通知，旧实现稳定失败。修复将行号栏预留移到 clip view 接收 frame 的入口，先约束尺寸，再交给 AppKit；相同尺寸不重复发布。原生选择、查找、换行、行号、非连续布局和语法着色预算继续使用共享阅读器。

## 验证范围

- 最终构建：Dev 0.1.153 / build 154，`make build` 通过；任务期间同步了已进入本地 `main` 的 OAuth 修改。
- `make verify AREAS="preview-renderers"` 通过，覆盖原生文字/行号像素、横向滚动、字体变化、视口与共享预览控件。其相关生产输入在随后同步 `main` 时没有变化，复用该证据。
- `make verify AREAS="memory popovers"` 覆盖视口稳定性、16 条共 63,360 字节的中文/emoji 正文、空/截断结果、缓存和原生保存排空，以及技能源码滚动与弹窗环境。
- 测试过程发现诊断探针保留的 capture suite 设置导致「记忆默认关闭」断言失败；确认属于检查偏好隔离问题后，按现有模型检查的方式在入口及退出清理检查自身的 suite，保留原断言。
- 授权后的真实窗口复核使用同一会话和全局记忆库：打开 2 次、关闭 1 次、刷新 1 次；正文正常显示，滚动到底部再刷新后保留阅读位置，关闭后能够重新打开。
