## 实现

- OMP 分块重组、base64 和完整 JSON 解码在 stdio 读取线程完成，主线程只接收解码结果。逻辑帧上限 64 MiB、1,024 块；重复首块、乱序、长度不符和嵌套 chunk 被拒绝。直接追加保留的缓冲，避免每块复制已有数据；退出后清除残留缓冲。消息积压按完整逻辑帧计费，保留 256 MiB 上限。
- 请求完成、失败或取消时立即取消对应的超时任务。每次注册有独立 generation，旧超时和迟到取消不能删除同 ID 的后续请求；同时在途的重复 ID 在发送前被拒绝。匹配 ID 但命令不同的回复不能成为成功结果或能力证据。
- 新建会话的文件无法读取且原文件未能保留时，阻止发送、预热、分支、周期保存和退出保存，保留草稿及可读的近期 6 轮。权限/I/O 失败不当作新空白会话；修复测试存储障碍并重开后再次尝试保留原字节。全部文件复制成功后才删除原文件，并为每次保留创建独立目录，避免部分复制失败或同秒重试造成恢复引用丢失。验证只使用本轮新建并主动损坏的测试文件，不处理已有用户会话。
- 新的 P5 资源负载使用当前分段格式和完成标记，先读取近期 6 轮，再加载完整万条记录。旧 P0 回放和既有历史记录仍保留为以前的证据，本轮不执行迁移流程。
- 修复侧栏与预览同时打开时窄聊天栏的顶部按钮裁切。空间不足时，已有 Hydra、分支、项目和会话按钮收进原生 SwiftUI popover，复用 Chrome 控件、材质及中文文案。打开后聚焦面板，Escape 关闭面板树并返回输入框；宽度改变时撤销失去锚点的面板。宽度沿用已有 pane 几何，不增加持续采样或计时器。
- 测量器通过本次 GUI 的 launchd PID 域枚举 WebContent、Networking 和 GPU 实例，并核对 PID/服务名。新启动时间、相同进程名和父进程为 launchd 均不单独作为归属依据。只保存 PID 和服务归属证据，不保存 launchctl 中的环境变量。无法读取或格式未知时保持未知。
- MCP 是本地合成服务器，经实际 OMP 初始化及 `tools/list`；其 PID 由测试服务日志确认，单独计量。GUI 没有新增 MCP hub 或执行调度器。生产采样仍默认关闭。

## GUI、资源与归档

本轮在获得明确启动/退出授权后使用隔离 Dev 窗口。中文和英文的实际 AppKit/SwiftUI 控件、键盘切换及 Unicode 草稿保留已检查。最终构建的中文快速检查中，owner 目视确认 Markdown 的正文、表格、代码和公式均正常。Unicode 检查使用原生粘贴，并非真实中文输入法组合验收。自动完整负载每轮为 100 次切换、20 次预览开关、30 秒稳定及前后各 60 秒空闲采样。GUI、OMP、MCP 和已核对的 WebKit 分项分别记录。

自动窗口截图曾出现整块 WebKit 空白或只有公式空白，而实际挂载、尺寸、DOM、动画结束断言通过，owner 目视也确认正常。为此收紧了验收器：必须是当前窗口挂载、可见且非零尺寸的 WebView，DOM 非空，预览动画及临时快照已结束；不再仅凭 rendered token 判定。没有据此猜测并修改生产 Markdown 渲染器。截图现象保留为测量限制，不能用这些截图签发实际屏幕首帧 p95。一次检查窗口未收到 finish 标记而超时，记录为失败；后续快速检查及完整负载重新通过。

半屏窄窗口实际复验：聊天标题及收起的入口可见，全部原有按钮可访问，原生分支子面板可打开，文件预览可关闭并还原宽布局。首次 Escape 未关闭新面板，补上 SwiftUI 焦点与退出处理后，英文复验确认 Escape 可关闭面板及子面板树，焦点返回输入框；中文与 emoji 草稿在会话切换后保留。未发送这份测试草稿。中英文标签均检查；没有把这项局部检查当成完整辅助功能矩阵。

早期中文窗口使用 OMP 18.11.1，空闲 GUI 平均 CPU 为单核 0.071% / 0.053%，近期内容加载加布局为 108.33 ms。英文窗口使用 OMP 18.3.2，CPU 为 0.155% / 0.568%，近期内容加载加布局为 101.94 ms；完整索引加布局约 928 ms。两者都不是屏幕首帧 p95，且不与旧 P0 的旧格式冷加载作性能改善百分比比较。

英文窗口的新归属测量中，前后空闲样本均完整，GUI + OMP + 本地 MCP + WebKit 的同时 footprint 中位数从 523.91 MiB 到 483.44 MiB，增量 -40.47 MiB，满足 52.39 MiB 重复操作门槛。预览进程退出/重建时有 6 次归属不完整，相关总量标记未知，不能据此关闭全负载峰值覆盖。该判定区分稳定状态的内存回归和操作期间的峰值范围；未删除 CPU 突发或失败样本。

最终 0.1.34 / build 35 的中文完整负载使用 OMP 18.11.1：空闲 GUI CPU 为单核 0.033% / 0.043%，同时 footprint 中位数 374.39 → 359.33 MiB，增量 -15.06 MiB，满足 37.44 MiB 门槛。近期页面加布局 77.18 ms，完整索引加布局 924.84 ms，均不作为实际屏幕首帧 p95。前后空闲归属及读取完整，操作期间仍有 8 个不完整样本，因此新版活跃峰值范围保留未完成。

同为 0.1.34 / build 35、窄布局修复前的英文完整负载使用 18.3.2：四个测量阶段归属及 footprint 读取均完整，CPU 0.140% / 0.041%，450.24 → 456.96 MiB，增量 6.72 MiB，满足 45.02 MiB 门槛。该轮作为完整归属参考，未冒充最终窄布局版本或新版运行时的数据。采样间峰值仍不在覆盖范围内。

资源数据和去 PID 的汇总归档见 [P5 JSON](../evaluations/2026-10-16-p5/acceptance.json)。原始采样、协议事件元数据、失败记录及 12 秒 Instruments Animation Hitches 检查 trace 留在任务构建目录。该 trace 采集于前一版英文窗口的检查阶段，不能用于签发首帧延迟门槛。
