## 消息追加与队列

运行中可选择补充当前任务（`steer`）、任务结束后执行（`follow_up`），或明确停止并发送（`abort_and_prompt`）。这些请求交给 OMP 调度，GUI 不负责执行队列。图片在后台读取后随原生请求提交；图片不可读时整条消息在提交前失败。

队列分别显示待提交、提交中、已接收、已消费、失败及结果未知。已消费表示原生用户消息事件已出现，不代表模型任务成功完成。确认接收后才清除相应草稿；交错的响应按请求身份关联。超时、取消等待或进程退出不能证明请求未执行，因此结果未知的消息保留内容且不自动重发。

原生用户消息事件不携带请求 ID；逐条消费仅按完整文本、图片数及原生 steering 优先/FIFO 顺序确认。模板展开等变换导致无法匹配时保留原消息。已获接收确认且原生处理结束的记录显示“OMP 已完成处理”，同时说明无法核实逐条消费；不会伪造持久化条目映射，也不会用队列为空解除未知送达状态。

仅未提交及明确失败的草稿可以编辑、删除、排序。已接收的原生队列不提供本机接口没有支持的撤回、修改或优先级控制。重开聊天时，尚未确认完成的提交转为未知，继续保护内容。

## 历史、分支及文件恢复

Dev 0.1.47 / build 48 已删除会话记录面板、历史树/条目浏览、上下文分页和独立 fork。正常聊天记录仍保存、恢复并展示；编辑消息前在后台读取持久化条目，沿 `leafId` / `parentId` 确认当前路径和原生用户身份。

编辑历史用户消息使用公开 `branch` 接口，随后读取 `get_state`，采用 OMP 创建的新会话文件和 ID。分支前先保存原 GUI 历史副本；成功后原路径作为“原会话”保留，当前聊天恢复编辑草稿。附件缺少本地副本时，从持久化图片数据恢复。任务清单和模型状态重新采用 OMP 的新分支状态。

GUI 保存每条用户消息的实际原生输入（包含附加上下文）、图片数量、持久化条目 ID 及所属会话文件。旧历史只有在完整顺序和内容可靠对应时才补充映射；无法关联时仍可阅读，分支操作不可用。不会用相似文本猜测目标，也不会用文本重放替代原生分支。

文件恢复是独立选项，默认关闭。启用时沿用检查点、变更预览和外部修改冲突保护，单独报告恢复结果。原生分支成功而文件恢复失败时，编辑内容留在输入框，避免自动提交到错误的文件状态。扩展拒绝分支时保留原会话；响应丢失或新身份无法确认时关闭该连接，避免向错误的原生会话继续写入。

steering 将 bash 转后台时，原生 `details.async` 仅表示归还控制权，不能当作写文件已经结束。GUI 保留该命令的 before-tree，到 OMP 确认整次工作结束后结算，并将实际工具变更归到原显示轮次。文件恢复分别报告恢复数和因后续修改而保留的文件数；部分恢复返回未完全恢复。新检查点使用 turn UUID，原会话保留的检查点不会被分支后重用的轮次序号覆盖；旧存储的 ref 仍可读取。

队列消费事件只划分显示轮次，不提供精确的文件检查点边界。因此这些轮次不继承上一轮的检查点，文件恢复不可用，原生会话分支仍独立可用。

会话记录专用的 `get_tree`、`get_messages_page`、独立 `fork` 及其模型/缓存已移除。消息编辑继续使用 `get_entries` 和原生 `branch`，不通过重放输入重建会话。

## 上下文管理

从用量面板打开现有上下文管理，支持自定义压缩说明、自动压缩的会话级开关、原生压缩阶段与结果、handoff 以及 HTML 导出。自动压缩开关不修改外部活动 profile。handoff 按 OMP 的接口在当前会话中生成摘要，并在运行时提供路径时展示保存文档。

原生未提供数值进度时仅显示工作状态；缺失 token 分项和费用显示未知。状态查询和统计查询合并，过期响应不能覆盖更新的生命周期。打开面板本身不会启动 OMP。

上下文变更仅在确认空闲且无原生队列、审批、子任务或其他维护操作时执行。请求结果未知时保持请求身份和进程保护，等待其实际迟到响应或连接关闭，不能仅依据 `get_state.isSettled` 解除保护。

## 验证范围

使用 `make build` 和无窗口生产协议检查。`make verify AREAS="history"` 验证活动路径、保守映射和损坏历史；`make verify AREAS="workflows"` 使用确定性 RPC 对端连接实际编译的服务，覆盖交错提交、接收与消费、图片、拒绝、取消等待、迟到确认、停止并发送、上下文操作和分支身份。
