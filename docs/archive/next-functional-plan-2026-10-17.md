## 目标与交付范围

下一阶段以「让用户控制并理解 OMP 已有的原生执行能力」为主线：先减少流式数据成本、接通原生运行选项，再增加目标执行与旁问。界面使用 SwiftUI/AppKit，扩展现有 Composer、Usage 和 Hydra 入口；不另建常驻控制中心。

| 顺序 | 工作包 | 用户得到什么 | 优先级与依赖 | 初步工程量 |
| --- | --- | --- | --- | --- |
| 1 | N0：增量传输与能力边界 | 长回复少传重复快照；旧 OMP 正常回退 | 必做；所有后续包的基础 | 2–3 日 |
| 2 | N1：原生 Fast 与重试控制 | 明确请求/实际速度状态；原生重试时可停止重试 | 必做；依赖 N0 的状态契约 | 2–3 日 |
| 3 | N2：原生目标执行 | 目标、预算、原生进度事实、暂停/恢复/放弃 | 核心新增；依赖 N0，运行时须支持 Goal RPC | 4–6 日 |
| 4 | N3：原生旁问 | 主任务继续运行时解释问题、同主题追问、取消 | 核心新增；依赖 N0，运行时须支持 BTW RPC | 4–6 日 |
| 5 | N4：原生 Slow 与缓存预热 | 在支持的模型上显式选择资源/服务策略 | 条件交付；依赖 N1，不能阻塞核心新增 | 2–4 日 |

## 接口依据与兼容策略

静态读取的本机 npm OMP 是 18.3.2。官方研究固定在 [470b7ef](https://github.com/can1357/oh-my-pi/tree/470b7efb67673960d37e3e64584669e6e9caad1c)，该提交的包声明为 18.11.2；它不能证明已发布版本、最低支持版本或本机进程的能力。历史 18.11.1 验收也不自动覆盖新接口。

| 能力 | 18.3.2 源码事实 | 固定官方源码事实 | GUI 当前缺口 |
| --- | --- | --- | --- |
| Delta 投影 | `set_event_filter` 有事件过滤，无新投影字段 | `messageUpdates: "delta"`，响应回显生效模式 | decoder 已消费增量，尚未请求原生投影 |
| Fast | 有 `set_fast_mode` | 区分 `enabled` 与 `active` | 只读 enabled，未接通设置请求/原生模型适用性 |
| Retry | 有 `set_auto_retry`、`abort_retry` | 保留原生重试及相关事件 | 已显示部分 retrying 状态，缺针对性控制 |
| Goal | 无公开 Goal RPC | `get/create/resume/pause/drop`，原生续跑 | 无原生目标状态或操作入口 |
| BTW | 无公开 BTW RPC | `btw`、`btw_cancel`、`get_btw_history` | 无旁问流程 |
| Slow / warming | 无对应公开 RPC | `set_slow_mode`、`set_cache_warming` | 无针对性入口 |
| Plan mode | RPC 无完整入口 | RPC 仍无完整入口；SDK 有部分状态原语 | 非 build 模式被拒绝，不能据继承的 PlanCard 宣称支持 |

接口参考：[RPC 类型](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/modes/rpc/rpc-types.ts)、[原生 RPC 实现](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/modes/rpc/rpc-mode.ts)。本地接入基础见 [OMPCapabilities](../../OMPGUI/Core/Models/OMPCapabilities.swift)、[OMPSession](../../OMPGUI/Services/Providers/OMPSession.swift)及 [OMPEventDecoder](../../OMPGUI/Services/Providers/OMPEventDecoder.swift)。

共同规则：

1. 能力证据按进程保存。成功且结果结构有效才确认支持；精确 unknown-command 才确认不支持；其他错误、超时保持未知。更换 executable、环境或会话身份时清除失效证据。
2. 有轻量只读入口时先读，如 `goal op:get`。没有只读查询的变更命令，不用「开再关」、空参数或默认值写入来探测。用户首次明确操作可以提交一次真实请求，界面显示待确认，不预先宣称已生效。
3. 能力未知与操作结果未知分别建模。操作超时后保留 request ID、原草稿及必要的运行保护，等待匹配的迟到回复或进程结束，不自动重发。
4. 状态字段缺失显示未知/沿用原生；不推断为关闭。读状态能力不等于已证明写命令可用。原生拒绝只影响对应功能，基本聊天继续可用。
5. 新能力不要求所有用户升级 OMP，不引入另一套 SDK 仿真执行路径。旧 npm 与 standalone 都保留已有路径；仅有公开 SDK 的功能不能被包装成通用 RPC 能力。

## N0：先减少流式成本

**实现范围**

- 在协议与 decoder 就绪后，真实请求 `set_event_filter(events: null, messageUpdates: "delta")`。仅响应明确回显 `messageUpdates == "delta"` 才记录启用；旧版忽略新字段或拒绝时继续现有 full 模式。
- 第一版保持 `events: null`，避免事件 allowlist 漏掉目标、重试、缓存或未来原生事件。此项是期望的传输设置，不执行工具或模型任务。
- 保留 `messageId`、内容索引、完整 `message_end`、协议 v2 分块、已消费消息和所有队列/settled 语义；不要把 `agent_end` 当完整聊天记录替换。
- 复用既有查询合并、generation 和取消机制，补齐后续工作包需要的状态类型；不增加诊断页面、版本扫描或启动时全量探测。

**验收**：full/delta 同负载产生相同文本、工具参数和最终结果；中途切换、未知字段、旧版无回显、分块末消息均正确；不丢审批/问答、worker、队列或 settled 事实。用一次隔离的长文本/工具参数负载比较传输字节与解析分配，记录收益，不能预写百分比。共享功能检查覆盖协议差异，测量作为独立 benchmark。

依据：[事件投影](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/modes/rpc/rpc-session-events.ts)。

## N1：接通原生运行选项与重试控制

**产品与 UI**

- 在现有模型/effort 控件与 Usage 详情内接通 Fast。紧凑显示实际状态，详情区区分用户请求与 OMP 实际采用；不能只更新 `Thread.fastMode` 就视为成功。
- 模型适用性以原生字段/结果为依据，不从 provider 名称猜测。更换模型后重读相关状态，避免沿用前一个模型的能力；旧版缺 actual 字段时不编造实际生效状态。
- 复用当前 retrying 提示，原生提供时显示次数、等待时长和原因，并提供 `abort_retry`。本包不开发 GUI 重试循环，也不把「停止重试」等同于停止所有原生任务。
- 自动重试的会话 override 仅在原生接口语义确认后开放；没有当前值时用明确的设置动作，不能用一个假定已知的开关。不能实现原生未提供的「还原 override」操作。

**实现与验收**

- 控制通过 `OMPSession` 发公开请求，在原生确认后提交 UI 状态。忙碌期间的模型/effort/速度改变遵守原生实际生效时机，不抢占工具和审批。
- 覆盖不支持的模型、enabled/active 不一致、切模型、原生失败、超时及迟到回复；停止重试后最终运行状态仍以原生生命周期为准。
- 保留草稿、现有模型角色和原生默认值；会话设置不能误写 profile。Fast 的费用/速度不作 GUI 保证。

## N2：原生目标执行

**用户流程**：在当前会话的原生 sheet 中输入目标和可选 token 预算，创建后在现有顶部进度区域显示简短目标摘要。展开查看原生状态、已用 token/时间、预算及暂停/恢复/放弃动作；todo 清单继续显示步骤，Hydra 继续显示 worker，不复制第二套任务列表。

**原生职责与状态**

- 使用 `goal op:get/create/resume/pause/drop`、`get_state.goal` 与 `goal_updated`。目标标识、预算、累计消耗、终态均来自 OMP；无原生完成比例时不绘制虚假的百分比进度。
- OMP 决定工具集、持久化和是否继续下一轮。只有原生 `goal.continuationModes` 包含 RPC 且原生实际执行时，才呈现连续执行；GUI 不追加定时器、循环 prompt、自动恢复或后台调度。
- 创建前区分「接口支持」「原生功能开启」「当前状态允许」。配置未开或计划模式冲突时保留输入并展示原生拒绝，不能自动改全局配置来通过。
- 暂停、停止当前轮、放弃目标保留原生差异。进程恢复后重新读取目标；原生恢复为暂停时，等待用户恢复。
- `goal: null` 本身不能区分完成、放弃或没有目标；只在匹配的原生终态证据存在时显示完成。重连后无法证明终态则保持未知，不扫描历史条目补造结论。
- 接入既有 activity/settled 与回收保护，覆盖待续跑、排队、审批、重试、压缩和进程退出；目标存在不自动等于正在工作，也不能让 GUI 空转保活。

**验收**：创建/暂停/恢复/放弃、预算用尽、原生完成、外部原生工具改变目标、abort、进程恢复、会话切换和迟到回复均保持同一原生身份；无 RPC 续跑配置时不模拟续跑。旧版明确不支持时隐藏不可用动作并说明原因，正常聊天不受影响。

依据：[Goal RPC 控制器](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/modes/rpc/rpc-goal.ts)、[原生 Goal 状态](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/goals/state.ts)。

## N3：不打断执行的原生旁问

**用户流程**：Composer 附近增加一个紧凑旁问入口，打开原生 sheet，在主任务继续运行时询问当前工作的解释。呈现一个主题、文本回答、同主题追问和取消；旁问不投递成 steering/follow-up，也不冒充可调用工具的另一个 worker。

**实现范围**

- 使用 `btw`、`btw_cancel`、`btw_delta` 与 `btw_record`。按原生 record ID、session 和 generation 区分流，终态快照校正增量；同时最多一个原生旁问。
- 主聊天和旁问的输入、忙闲、错误、取消与结果分别归属；费用有原生分项才单列，不自行估算或重复计费。原生 sidecar 负责持久化，不另建 GUI 旁问数据库。终态 `btw_record` 可能早于落盘，不能把回答完成当成已保存；收到原生保存失败时明确反馈。未知送达不自动重发。
- 关闭 sheet 释放渲染器和布局缓存，模型只保留预算内的当前主题状态；重开从该状态恢复，不全量拉历史补齐。关闭不偷偷取消用户仍在运行的旁问；取消是明确动作。当前旁问仍运行时，既有进程回收必须保留它，主聊天不能因此显示为正在生成主回复。
- 会话切换、编辑消息 branch、进程退出等导致的旁问取消/中断以原生事实为准；不能重新连接后自动再次提问。
- 首版只显示本次连接中的当前主题及其追问，不开发主题历史浏览器。`get_btw_history` 不分页，不能作为每次打开/启动的轻量 probe 或常驻刷新。跨连接恢复先延期；待有定向/分页公开接口，或另行证明按需全量读取满足预算后再评估。
- `btw_record` 与成功响应本身也包含累计追问。一个主题拟限 16 轮或累计原生问答正文 1 MiB，达到任一边界后不再向该主题追加，允许新主题；不删除原生记录。单次超大输出仍可能超过协议上限，终态缺失或 `rpc_frame_error` 保持结果未知，不自动重问，不扩大接收预算。

**验收**：主回复持续流式时旁问仍可独立问答；只读无工具语义、单旁问限制、追问/取消、先 delta 后终态校正、进程退出、中断和 sidecar 保存失败均不污染主聊天；超长回答及累计追问有界显示，原始结果由 OMP 负责保存，未确认持久化时不宣称已保存。首用请求不支持时保留问题并明确反馈。

依据：[BTW RPC 控制器](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/modes/rpc/rpc-btw.ts)、[原生旁问存储](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/packages/coding-agent/src/session/btw-history.ts)。

## N4：有条件地开放 Slow 与缓存预热

N1 完成后分别实现，单项接口未通过门槛就延期，不拖住 N2/N3。

- **Slow**：先读原生 `slowModeSupported`、`slowModeEnabled`、`slowModeScope`。仅此会话与持久全局设置用不同说明；Direct Anthropic 的全局行为必须在用户执行前明确，不能归入「仅此会话」。界面按原生字段建模，不把 Fast/Slow 强制压成一个想当然互斥的三档选择器。
- **缓存预热**：在 Usage 内提供原生 `off/streaming/idle` 的明确设置动作，展示已确认的会话 override 与原生 start/end 结果。默认沿用 OMP，GUI 不主动开启，不以缓存命中率低为由自动触发预热。
- 原生未提供当前模式读取时保持未知；没有原生 reset/inherit 请求时，不提供虚假的恢复默认操作。每次变更只发一次原生请求。
- 预热可能产生模型请求、网络活动与费用；展示原生提供的消耗明细。它已计入原生 session stats，细分展示不能再次累加总费用。隐藏界面不增加采样或另一个保温计时器。

**验收**：不支持模型、全局/会话 scope、外部配置更改后的可观察状态、预热 hit/miss/error/aborted、停止及进程退出均正确；缺失字段保持未知。原生没有提供新状态事件时，复用既有按需状态读取，不增加后台轮询。

依据：[RPC 运行选项与缓存事件](https://github.com/can1357/oh-my-pi/blob/470b7efb67673960d37e3e64584669e6e9caad1c/docs/rpc.md)。

## 原生 UI 与资源完成标准

按 [UI 约定](../ui-guidelines.md)复用 Chrome、TypeScale、AppTheme 与 Hydra 资产。主体使用 SwiftUI 的普通布局、原生 picker/switch、List/DisclosureGroup、sheet/popover；文本渲染继续复用现有 AppKit/TextKit/SwiftMath。新控制面不增加 WebView、前端运行时或持续动画。

Liquid Glass 仅显式用于符合规则的紧凑单行按钮/字段；侧栏审批/回答等待胶囊保留指定语义颜色例外。新目标、旁问、资源状态不能借用这一例外。内容、大面板、列表行和普通状态使用语义文字、细微填色与分隔线。

每包都必须满足：

- 所有新增用户文案在 `Localizable.xcstrings` 有忠实 zh-Hans；用户内容、模型名、路径和 OMP 原文 verbatim。键盘、焦点归还、Escape、输入法组合、窄窗口、多窗口身份不得退化。
- 主线程只提交紧凑状态，协议/大文本处理复用现有后台路径。更新合并且快照有界；隐藏界面不新增历史读取、全量索引、周期轮询、worker 日志消费者或保活进程。
- 复用现有协议 64 MiB 重组/256 MiB backlog、Hydra 简报 128 KiB/32 文件、报告显示 64 KiB，以及[文件预览预算](../file-preview.md)，不因新页面扩张。
- 新增目标/旁问输入拟复用 128 KiB 文本提交上限；超限在提交前明确拒绝，不静默裁剪。目标显示正文拟限 64 KiB；当前旁问主题所有保留问答的合计显示正文拟限 64 KiB，最多保留 16 轮，超限先淘汰旧显示片段并标明省略，不裁剪提交原文或原生记录。完整结果由 OMP 负责保存，未确认持久化时不宣称已保存。实现时把确切边界写入生产常量和对应说明，不把这些拟定值冒充现有实现。
- 每个活跃会话只保留一个目标状态和一个当前旁问主题的有界显示状态；关闭界面释放额外 renderer/大正文缓存。跨会话小状态复用既有加载/回收策略，不建立无限增长的副本。
- 保留性能模式、减少透明度/动态效果及辅助功能回退。测量默认关闭，不增加生产遥测面板。

## 性能门槛与 Q 验收

性能从 N0 起参与设计，Q 统一做一次受控现场验收。沿用[当前目标](../status.md)，先确定测量定义、硬件、原生版本和负载，再比较同负载父提交；不能以 helper、主线程心跳或布局结束代替实际屏幕成绩。

| 项目 | 目标/判定 |
| --- | --- |
| 用户输入与菜单 | 受控负载实际响应 p95 ≤ 100 ms |
| 缓存会话首屏 | 实际首屏 p95 ≤ 150 ms |
| 万条消息冷首屏 | 固定新生成数据，实际首屏 p95 ≤ 800 ms |
| 普通流式回复 | 定义好的普通可见负载，事件接收到屏幕 p95 ≤ 100 ms |
| 压力负载 | 大输出、多 worker、大文档和旁问并发下输入不饥饿、内存有界；另报刷新分布，不套统一 100 ms |
| 无原生后台工作时的空闲 GUI | 平均 CPU ≤ 单核 1%；原生目标/预热/旁问工作负载单独归因 |
| 重复操作 | 100 次聊天切换、20 次预览开关后稳定 30 秒，增量 ≤ max(基线 10%, 20 MiB)；新增 sheet 开关纳入同类回收观察 |
| 进程账本 | 区分 GUI、OMP/Bun、worker、WebKit 和 MCP，报告各角色与整体峰值，归属缺失标记未完成 |

当前流式合并已因滚动/多 worker 使用不同间隔，不能在未测量时保证所有负载统一 100 ms。上述目标仍是待关闭门槛，不是本计划已经取得的成绩。

Q 现场范围包含中英窄窗口、键盘/审批问答回归、最终 Liquid Glass 合成、VoiceOver、真实输入法、睡眠唤醒和减少动态效果。复用已有有效证据，仅测受影响路径；明确记载不能完成的项目，不反复扩矩阵直至出现有利结果。GUI 启动/退出及现场驱动仍按 owner 的明确授权安排。

## 实施分工、验证与停止规则

1. 每包开工先读取当前源码和本计划的对应接口，确定支持/不支持/未知样本及最小检查集合；新接口的 native 验证限于直接 RPC 路径，不附加无关模型/账号矩阵。
2. Core 增加原生事实模型；Services 负责请求、能力、取消和 I/O；App 组合状态与用户动作；UI 复用 Chrome。避免继续把协议和大正文处理堆入 `ThreadRuntime`。
3. N0/N1 可先以旧版本 fixture 交付；N2/N3 要在明确路径、隔离 profile 的支持版本上确认公开接口。18.3.2 的不支持路径复用 fixture，不为每个包重跑相同版本矩阵。支持版本只在实际原生证据产生后记入范围。
4. 编译源码/资源变更做一次增量 `make build`，再用 `make verify AREAS="..."` 选受影响模块。N0 通常是 `rpc`，N1 是 `config workflows`，N2 是 `workflows lifecycle`，N3 是 `rpc workflows`；这些是开工选项，最终以实际触达确定，不机械串联为整套检查。
5. 新增有独立行为契约的 Goal/BTW/运行选项检查放 `tests/` 并只在 `tests/catalog.py` 登记一次，使用 `goal_tests`、`side_question_tests`、`run_options_tests` 等行为命名及明确输入/工具/超时/依赖。功能 fixture 不依赖已安装 OMP 或 benchmark；不加实现镜像测试。
6. Native 接口、benchmark 和 GUI 手动验收分开安排；不把 Q 的负载自动挂到日常验证。失败先阅读相关生产/检查源码，判断实现、预期或环境原因，再只重跑受影响失败项。选定检查通过即停止。
7. 每包在独立 `codex/` task worktree 中开发，从 local `main` 起步，整合为一个 commit 后 fast-forward；同步相关当前指南、Unreleased 和适用版本文件。保留 worktree，清理由 owner 单独决定。无远端 push/PR/发布。

本次规划文档只选 `make verify TIER=static AREAS="documentation"`，不触发应用构建或运行。

## 暂缓项与重新进入条件

| 项目 | 本阶段决定 | 重新进入所需证据 |
| --- | --- | --- |
| 原生计划模式 | 不承诺交付，也不把 UI plan 开关当已接通 | 完整公开进入、工具限制、审批、执行交接及退出生命周期；SDK state setter 本身不足。最多一次 1 日接口核对，失败即记录阻塞，不拼私有 TUI/ACP 或伪发 slash |
| agent/skill 定义可视化 | 后置，不扩成命令或技能启动器 | OMP 提供稳定公开结构化发现，能区分定义、可发现与本轮实际启用，且支持有界按需读取；不能自己扫描/解析一套发现规则 |
| Hydra 隔离结果手动应用 | 保持现有事实展示 | OMP 提供可确认的公开应用操作、冲突及取消语义；不写 GUI 合并器 |
| memory/learning、LSP 等专用新展示 | 暂不增加面板 | 有稳定结果结构、明确高频用户任务及复用入口的收益；工具名/图标不构成接口证据 |
| BTW 跨连接主题恢复 | 首版延期 | 定向/分页公开读取，或受控证明按需全量读取满足资源预算；不重建会话记录浏览系统 |

重新进入前先核对本表与删除清单，避免每轮把同一缺口或被删除的入口重新包装为新阶段。完成 N0–N3、符合条件的 N4，以及明确记载的 Q 结果后结束本阶段；未满足接口门槛的项目保留延期原因，不由 GUI 模拟补齐。
