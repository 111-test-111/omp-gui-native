# OMP 原生能力开发计划

> 历史记录：仅代表原文所列日期、版本及验收范围，不是当前操作指南。 当前已移除的收件箱、会话记录、独立 fork 和诊断入口不因本文的历史描述而恢复为功能。 当前入口见[文档索引](../README.md)和[功能状态与验收边界](../status.md)。

2026-10-16。基线为本地 main `6a62798` 与本机 OMP 18.3.2。开发分支为 `codex/omp-native-roadmap`，在独立任务 worktree 中实施。最初暂不合并 main；owner 后续明确要求完成 P3/P4 验收后集成整个相关分支树，现按此执行，不推送远端。见 [验收记录](p3-p4-acceptance-2026-10-16.md)及[集成检查](main-integration-audit-2026-10-16.md)。

下一阶段以 OMP 原生会话工作流、原生能力入口和资源控制为主线，先完成日常使用的关键闭环，再扩展功能面。按一名主开发者估算完整阶段约 6–8 周；首批交付 P0–P2，约 3–4 周。估算包含验证与修复，不包含 OMP 上游接口开发、安装升级或发布。

## 开发原则

1. OMP 是唯一运行时，负责模型、认证、模型角色、MCP、技能、扩展、子代理调度、隔离与任务结果应用。GUI 使用公开 CLI、RPC、SDK 接口。
2. 新增交互使用 SwiftUI 和必要的 AppKit，复用 Chrome、Hydra 资产、系统材质、语义颜色和现有字体体系。键盘、VoiceOver、窄窗口及减少动态效果均进入验收。
3. 性能和资源占用贯穿每一阶段。测量 GUI、OMP、MCP 及 WebKit 的总成本，不能用 GUI 单个进程代表整个产品。
4. 以运行中的实际接口响应决定能力是否可用，区分支持、不支持和未知。新版文档不构成本机支持证据。
5. 保持 Core → Services/UI → App 依赖方向和独立数据目录；OMP 活动 profile 由外部管理，不导入其他产品数据。
6. 每项开发任务使用任务 worktree 和 `codex/` 分支，按任务形成一个提交；按 owner 最新要求将已验收的计划树集成本地 main。新增文案同步 zh-Hans，保留来源、许可、商标及既有图标。

## 现有基础与缺口

已经接通模型与账号配置、MCP、Hydra、任务清单、文件预览、聊天虚拟化、流式合并和闲置资源释放。

- 主会话“立即发送”先中断再发送，尚未使用原生 steering。
- 历史回退创建新会话并补入保留文本，尚未使用原生分支。
- 扩展对话框部分接入，状态、文本组件与编辑器预填仍有缺口。
- 空闲回收需要统一使用 OMP 实际状态，区分单轮回复结束与后台工作全部结束。
- 能力、配置查询与性能数据需要统一记录及可重复验收。

## P0 能力识别 会话状态与性能基线

预计 3–4 天。建立按进程保存的能力记录，成功响应证明支持，明确的未知命令证明不支持；超时、不可用注册表和其他失败保持未知。版本只作为诊断信息。可选接口缺失不阻断基本聊天。配置、模型和状态的同类请求合并，避免每次打开页面启动重复 CLI。

将回复中、等待用户、原生队列、压缩或重试、后台工作、完全结束分别建模。进程回收综合原生 settled、待处理请求、子代理和未保存数据，不能只依据 GUI 已空闲。旧状态回复不能覆盖更新的生命周期事件。

扩展已有 SwitchLatency 与 signpost，记录启动、聊天切换、流式刷新、历史读取、预览和进程退出。建立固定输入、无窗口协议回放、资源采样和 JSON 报告。生产默认不运行持续资源采样。

验收：旧版可选接口缺失仍可聊天；后台工作不会被空闲回收误停；支持/不支持/未知可检查；报告注明测量进程、覆盖范围及缺失数据。

当前进度：P0 基础实现、构建与无窗口回归已完成；经授权继续验证实际 Dev 窗口和本机 OMP 18.3.2，建立 100 次聊天切换 / 20 次预览开关的资源基线，并修复万条旧历史的批量恢复卡顿。P0 仍待 WebKit 完整归属、真实模型/MCP、屏幕首帧和跨版本等验收，暂不标记全面达标。具体结果见 [P0 实施与验证](p0-runtime-baseline.md)。

2026-10-16 后续安排：按 owner 要求暂缓 P0 剩余验收，继续推进 P1、P2 开发；不将 P0 验收作为后续实现的阻塞条件。

## P1 原生追加指令与消息队列

预计 5–6 天。输入框提供三种清楚的操作：补充当前任务使用原生 steering；任务结束后执行使用原生 follow-up；停止并发送使用明确的中断操作。交付时机遵循 OMP 和实际模型能力。

沿用队列界面，区分待提交、已接收、已执行和失败。确认接收后才清除草稿，超时结果未知不盲目重发。请求关联扩展为多请求记录，处理交错回复与结束事件。OMP 持有执行队列，GUI 只编辑未提交草稿；已接收消息的撤回、修改和优先级调整仅在公开接口支持时开放。

验收：连续追加、工具执行、审批等待、图片、发送失败和进程退出都不丢消息、不重复执行，输入与滚动保持响应。

当前进度：本机 OMP 18.3.2 + K3 验收通过。实际审批等待中追加 steering 和图片 follow-up、逐条接收/消费、最终回复保留已验证；失败、未知送达及进程退出由生产协议回归覆盖。见 [P1 / P2 原生会话工作流](p1-p2-native-workflows.md)及[验收记录](p1-p2-acceptance-2026-10-16.md)。

## P2 原生历史分支 恢复与上下文管理

预计 6–8 天。优先接入当前版本支持的历史用户消息分支，保留旧路径、恢复编辑内容，采用 OMP 返回的新会话身份。保存 GUI 与原生持久化条目的映射。后续 Dev 0.1.47 / build 48 已按 owner 要求删除会话记录面板及专用历史导航、条目详情和分页，不再列入交付范围。

会话分支与恢复项目文件分别操作、分别报告。文件恢复沿用变更预览与冲突检查；会话成功不表示文件恢复成功。扩展用量面板，增加自定义压缩说明、自动压缩状态、压缩进度与结果、handoff 和导出。统计以原生数据为准，缺失分项显示未知。

独立 fork 及 `get_tree` 浏览已随会话记录功能删除。消息编辑保留原生 `branch` 和附件恢复；不提供任意历史节点切换。

验收：分支后的工具、附件、清单和模型一致；扩展拒绝分支时原会话仍可用；原生会话身份变化时拒绝过期历史。

当前进度：本机支持范围的历史验收记录保留。真实分支、文件恢复、原会话/草稿保留、HTML 导出、自定义压缩、压缩后新对话及 handoff 已验证；当时 handoff 未返回文件路径。文件冲突与 checkpoint UUID 隔离有定向回归。旧版分页/游标验收仅为历史事实，当前验证范围见[工作流说明](p1-p2-native-workflows.md)，历史证据见[验收记录](p1-p2-acceptance-2026-10-16.md)。

## P3 技能 扩展 模型角色与 MCP 原生入口

预计 5–7 天。命令面板保留来源、别名、参数提示和子命令，区分内置、技能、扩展、自定义和 MCP prompts。技能由 OMP 执行，GUI 不维护另一套执行逻辑。

补全选项说明、多行编辑、预填、超时取消、状态文本、文本组件、编辑器更新和登录 URL。使用原生控件并限制组件尺寸与刷新频率。将常用模型角色及子代理设置提升为表单，展示有效值与可确认的范围；MCP 配置状态与连接状态分别显示。

插件清单、安装卸载及实时诊断先确认公开接口；只有 TUI 的能力提供终端入口。命令目录不充当完整安装清单。保留原生认证、未知配置字段和外部修改冲突保护。

验收：CLI 修改正确刷新、无未知字段丢失、项目/profile 范围清楚、状态均有原生依据。

当前进度：本机支持范围验收通过。32 项协议、14 项隔离真实 CLI 检查通过，另实跑原生插件安装/清单/诊断/卸载、真实登录 RPC 的本地合成 provider 回调、扩展对话框和设置表单。修复首次登录入口缺失及表单首开空值；MCP 配置与连接未知分别显示。未重新登录外部真实账号，详见 [P3 原生能力入口](p3-native-entrypoints.md)及[验收记录](p3-p4-acceptance-2026-10-16.md)。

## P4 Hydra 完善与文件上下文联动

预计 4–5 天。完善父子关系、任务来源、实际模型、工作目录、隔离、结果及产物关联。控制与结果应用依然由 OMP 决定，缺失能力不可用。

按实际订阅粒度降低不可见详情的事件负担，查看时订阅或增量补读，关闭后降级，保持历史连续。文件预览增加将选区或文件位置加入提问，保留路径、行号与所属 worktree。随后通过 OMP host tools 支持读取明确选中的上下文及打开文件位置，使用原生请求、取消和结果协议。

验收：主任务结束而子代理继续时状态正确；ID 复用不串记录；多 worktree 定位正确；隐藏面板不持续解析不可见内容。

当前进度：本机支持范围验收通过。47 项定向检查及 OMP 18.3.2 + K3 的真实 host tools、跨 worktree 定位、隔离子代理、隐藏/重开补读和最终结果通过；修复标题行在会话头之前时工作目录丢失。本机不存在子代理 stop/steer RPC，真实探测后正确禁用；未来支持路径及 ID 复用/取消竞态由协议回归覆盖。见 [P4 Hydra 与文件上下文](p4-hydra-file-context.md)及[验收记录](p3-p4-acceptance-2026-10-16.md)。

## P5 向前兼容与性能收口

预计 4–5 天。2026-10-16 按 owner 最新补充取消旧会话迁移、回填和旧数据验收；开发阶段只面向新会话。不扫描、重写或修复已存在旧会话。OMP 持有运行时事实，GUI 保存新会话的显示索引、草稿与界面状态。

覆盖 18.3.2 和固定的新版运行时，验证断连、未知事件、分块大消息、损坏历史、外部配置修改、取消竞态、睡眠唤醒。交付兼容矩阵、使用说明、基线报告和 Unreleased 记录。

验收：新会话在已验证的两版运行时中可用，失败可恢复，功能和资源门槛按真实测量结果核对。旧会话处理不在范围内。

进度、固定版本矩阵和资源测量见 [P5 向前兼容与验收](p5-forward-acceptance-2026-10-16.md)。owner 后续要求停止过度反复测试、尽快收尾并在本轮给出下一阶段方案，现按最新指示交付 [P6 原生工作台完整方案](p6-native-workbench-plan.md)。尚未完成的屏幕延迟、资源范围及现场矩阵继续列为质量门槛，不以构建或无窗口检查代替。P6 优先发挥 OMP 原生能力、使用 SwiftUI/AppKit 原生样式，并约束性能、资源及验证范围。

## 性能目标与测量口径

以下是拟定目标，不是现状成绩。P0 固定硬件、系统、编译模式、OMP 版本、输入及测量方法；修改目标必须记录依据。

| 项目 | 目标 |
| --- | --- |
| 输入、菜单与按钮响应 | p95 ≤ 100 ms |
| 已缓存聊天切换至可读首屏 | p95 ≤ 150 ms |
| 万条记录聊天冷首屏 | p95 ≤ 800 ms，历史分段加载 |
| 本地流式事件至显示 | p95 ≤ 100 ms，不含网络推理耗时 |
| 无活动任务时 GUI CPU | 稳态平均 ≤ 单核的 1% |
| 重复操作内存 | 100 次切换、20 次预览开关，返回同状态稳定 30 秒后，增量 ≤ max(基线的 10%, 20 MiB) |
| 性能回退 | 同负载关键指标恶化超过 10% 时分析并处理后验收 |

绝对内存预算按 GUI、预览引擎、每个 OMP 及其子进程分别记录 physical footprint、峰值和进程数。整应用首次测量后锁定预算；无窗口帮助进程数据不能冒充整应用数据。MCP 未能可靠辨认时列为 OMP 后代进程。WebKit XPC 通常不在 GUI 子树，必须明确指定或验证归属，不能将其他应用的 WebKit 算进来。读取失败是未知，不是零。

工程要求：大帧、历史、差异和语法处理在后台；沿用虚拟化与流式合并；按字节限制缓存；合并同类查询；不可见面板停止额外工作；回收仅针对确认结束且可安全保存的会话。固定数据覆盖长聊天、大输出、多子代理与大文档。

现有 Markdown 文件预览保留 WebKit 内容引擎，单独计量资源；新功能页面使用原生控件。现有验证见 [文件预览](../file-preview.md)。

## 验证与交付

使用 `make build`、已有检查脚本及针对协议/生命周期的回放，没有独立 Xcode test target。构建与无窗口检查不等于整应用交互通过。GUI 启动、整应用测量和打包在 owner 明确要求运行时进行。本次 P3/P4 验收使用独立 GUI 存储和测试 checkout，完成后按 owner 要求集成本地 main；worktree 留存。

原生计划模式开关、语音、输入预测等在后续候选池，待公开接口支持和资源收益评估通过再安排。
