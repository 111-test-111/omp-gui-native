## 清单保留规则

- `done` 修改任务状态，不清空清单。当前版本的完成检查也不会自动删除任务；模型仍可以调用 `rm` 清空。
- 有非空原生清单时，胶囊展示该清单。全部任务为 `completed` 后，即使原生清单清空，也保留最后的完成记录。
- 同一次 eval 中先完成、再清空时，通过 OMP 公共 `get_entries` 接口和返回的 `leafId` 找到当前分支上的完成记录。子代理通过 `get_subagent_messages` 独立读取自己的记录。
- 新的非空清单替换完成记录。新清单在一次 eval 中创建并清空时，最近的未完成清单阻止旧完成记录复活。未完成、阻塞或放弃状态不会被误判为“全部完成”。
- GUI 将展示记录存入自己的聊天历史；重开聊天后仍可展示。它不调用 `set_todos` 回填旧清单，OMP 的活动清单仍由 OMP 管理。

## 已修复的 GUI 缺口

| 链路 | 问题与处理 |
| --- | --- |
| eval 内 todo | 嵌套调用没有独立的 todo 工具事件。读取原生当前状态，必要时读取原生分支记录，覆盖直接调用、并发修改、完成后清空和恢复。 |
| stdout / 状态更新 | 密集 stdout 曾反复使状态读取过期。普通输出不触发查询；原生 todo 提交提示、工具结束及会话边界触发合并刷新，累计状态提示去重。 |
| eval 输入 | eval 被当作 shell 命令，标题只有名称而代码输入被丢弃。保留原始输入，旧聊天按原生调用 ID 恢复缺失输入。 |
| 结构化结果 | `cells`、`statusEvents`、`jsonOutputs`、`notice`、`async` 等数据没有进入详情。保留这些原生诊断，不将被代码捕获的内部失败改判为整个 eval 失败。 |
| 错误与后台消息 | 接收原生 `notice`、`auto_retry_start.errorMessage` 和可显示的 `async-result` 消息，展示持久化错误、重试原因和后台结果。 |
| 文件变更 | eval 标题是说明文字，不能据此判断 shell 是否只读或执行了 `cd`。eval 始终按可能写文件的命令处理，在聊天的 Git 工作区中跟踪变更。 |
| 异步元数据 | 状态读取及清单历史读取后重新检查版本，旧轮次的模型设置不能覆盖新轮次。 |
| 子代理 ID 复用 | 新工作会话重新创建解码器和消息前缀，关闭旧清单同步器，防止旧事件/调用记录覆盖新的工作会话。 |
| 保存与回退 | 完成记录关联到所属轮次，历史晚到时补齐关联；回退同时删除旧版未关联轮次的清单，避免被删除的记录复活。 |

## 已确认的 OMP 侧问题

在 OMP 18.3.2、启用 `tools.xdev` 的会话中，eval 内的以下调用成功修改内存清单，但不产生 todo 的持久化快照：

```javascript
await tool.write({
  path: "xd://todo",
  content: JSON.stringify({ op: "init", items: ["Mounted"] })
});
```

原生 SDK 验证结果：活动清单 `0/1`，`SessionManager.getBranch()` 中重建的持久化清单 `0/0`。恢复、分支重建或子代理 transcript 查询因而可能丢失这次更新。`src/eval/js/tool-bridge.ts` 仅在桥接名称为 `todo` 时调用 `persistTodoPhases`；Python 桥接也使用这条共享实现。GUI 无法通过原生历史恢复一项 OMP 没有记录的修改。

当前可靠的调用形式是：

```javascript
await tool.todo({ op: "init", items: ["Task"] });
```

这条路径的并发完成、清空与原生日志恢复均已验证。工具桥接同时明确拒绝 eval 内的 `checkpoint` / `rewind`，要求使用原生直接工具；这是 OMP 的接口约束。

## 验证与边界

- `make build` 通过；`make verify AREAS="todo"` 的 54 项生产解析器/同步器回归检查通过。
- `make verify AREAS="eval"` 的 39 项检查通过：使用编译后的真实解码器和 ThreadRuntime，无窗口启动，在独立存储中验证记录保留、历史加载、重开、错误与后台通知、输入恢复及子代理身份格式；回放原生 SDK 结果，并用实际 OMPSession RPC 客户端读取问题会话日志的副本，验证清空状态与完成记录恢复。
- 原生 SDK 在独立目录执行 eval，验证并发 todo、清空、读写、异常及内部错误；未发送模型提示，外部 HTTP 被禁用。
- 文件差异依赖聊天的 Git 工作区。eval 内任意 Python/JavaScript 代码绕到外部目录时，RPC 不提供完整的逐文件修改清单，GUI 不把未知外部写入归属于当前项目。
- 原生后台结果通知与嵌套工具的调用详情分别展示；工具调用返回不等于其后台工作已经结束。原生任务调度、后台作业状态与恢复策略仍由 OMP 管理。
