## 已实现

### 能力证据

`OMPCapabilities` 记录当前进程已请求命令的 `supported`、`unsupported` 或 `unknown`。成功响应证明支持；精确的未知命令错误证明不支持；其他错误和超时保留未知。只有匹配当前请求的回复参与记录，无对应请求和超时后迟到的回复不参与。

停止/引导子代理仅使用不含 worker ID 的原生参数校验进行安全探测，每个进程每项最多探测一次。基本聊天在模型目录、命令目录及可选子代理接口缺失时仍可使用。能力记录会传到 `ThreadRuntime.ompCapabilities`，尚未增加诊断页面；报告包含模拟进程的能力快照。

### 原生工作状态与回收

`OMPActivityTracker` 区分启动、回复、等待用户、队列、压缩、重试、后台、settled、未知及停止。生命周期事件推进 revision，旧 `get_state` 快照不得覆盖新事件。单轮 `agent_end` 不表示整个会话已结束，`session_settled` 也不能丢弃尚未确认的请求或未回答的对话框。

10 分钟闲置回收和内存 runtime 淘汰共用安全条件：原生确认 settled、无请求/对话框/队列/子任务、无历史操作/收尾/待发消息/额度等待。回收前必须成功保存未落盘快照。未知状态不授权自动回收；明确停止或退出仍走原有停止流程。

侧栏、时间线、完成通知和睡眠保护读取原生工作状态。进程意外退出会将延迟结果标记为失败，避免后台结束时误报成功。新增状态文案复用现有 SwiftUI/Chrome 展示，并有 zh-Hans 翻译。

### 查询与缓存

- 配置和设置发现合并同一上下文的在途请求，仅缓存成功结果 15 秒，保留一个上下文。
- 上下文包括可执行文件、环境及适用的工作目录；原生写入前后失效配置缓存，显式重试绕过已有缓存。
- 缓存仅保留原有白名单配置及登录状态，不缓存原始凭据响应。外部配置修改可通过强制刷新立即获取，普通设置页刷新最多受 15 秒缓存影响。
- 模型目录合并在途发现，丢弃旧可执行文件/环境结果。目录沿用显式刷新的生命周期，不宣称也有 15 秒 TTL。
- 会话 `get_state` 在活动 revision 和模型 revision 均相同时共享查询。旧查询仍可返回给等待者，但不会覆盖更新的活动状态。

### 性能记录

`OMP_GUI_PERFORMANCE=1` 开启 signpost 与内存统计。默认关闭，无持续采样线程或计时器。每类保留最近 256 个耗时，p50/p95 来自该窗口，count 和 maximum 覆盖该进程已记录的全部样本；不记录提示词、路径、账号或凭据。

| 指标 | 实际测量边界 |
| --- | --- |
| `sessionStartup` | `OMPSession.start` 整段，包含发现请求；本报告使用模拟对端 |
| `rpcRequest` | 单次相关请求等待，包含命令失败和超时 |
| `rpcReassembly` | 最后一个分块到达后的完整 JSON 解码与分发；不含分块传输或逐块累积 |
| `processShutdown` | 调用停止至等待进程退出完成 |
| `historyRead` | 读取并解码本地历史文档；不含布局和首帧 |
| `streamFlush` | 一批流式增量写入显示模型；不含事件等待及屏幕呈现 |
| `chatSwitch` | Dev 中选择聊天至下一次主 run loop 休眠；快速再次切换会结束前一个区间，不代表首帧 |
| `previewOpen` | 预览打开的异步加载路径；不包含所有缓存命中，也不代表渲染完成 |

P0 建立可比较的数据入口，没有据此宣称所有解析已移出主线程或整应用响应达标。后续性能优化必须依据实际 UI 测量定位。

## 重复验证

在任务 worktree 执行：

```sh
make build
make verify TIER=benchmark AREAS="lifecycle"
```

当前 benchmark:lifecycle 先验证默认关闭指标，再运行无窗口帮助进程；资源归属算法独立使用 functional:resources。固定负载包括 24 个并发发现请求、可选接口缺失、超时及迟到状态/响应、后台与意外退出、12 次 2 MiB 分块回复、10 次读取固定的万条历史，以及 20 组各 200 个流式增量。另检查指标缓冲上限；这批人工计时不计入基准结果。

当前基准产物在 `build.noindex/verification/runs/<run>/benchmark/lifecycle/`：`checks.log`、`checks.json`、`baseline.json` 及隔离 `storage/`。基准包含机器/系统/Swift 版本、父提交与 dirty 状态、生产 Swift/相关脚本指纹、生产 dylib 指纹、固定对端和负载指纹。计时来自生产类型，资源样本包含帮助进程与观测到的子进程。

资源采样器使用 `proc_pid_rusage` physical footprint 和 Mach 时间刻度，每轮采样后间隔 200 ms。以 PID 加启动身份跟踪进程，保留已知且随后重新挂父的子进程，拒绝复用的根 PID。明确提供 OMP/MCP/WebKit PID 后才标记相应角色；未知 OMP 后代单列，不能将其他应用的 WebKit 算入本应用。

不可读取或初次无法附加的进程使该次总量为 `null`，不是零。已退出的已知根单列为 absent。分组峰值是观测值，可能不同时发生，不能相加为总峰值。短命进程和采样间峰值可能遗漏；CPU 仅累加相邻样本中相同进程身份的时间差，同时列出可观察的进程秒数，多进程的进程秒数不等于墙钟时间。

## 首次无窗口基线（254510c）

最终构建和回归结果、无窗口基准摘要见同目录的 [P0 基准 JSON](../evaluations/2026-10-16-p0/baseline.json)。原始逐进程采样留在本地构建目录，归档摘要不包含 PID。

环境：Mac17,4，arm64，24 GiB RAM，macOS 27.2，Debug。`make build` 通过。P0 生产检查 102 项、默认关闭指标检查 2 项、资源归属检查 10 项、运行时回归 25 项、待办同步回归 54 项均通过；新增 4 项中文翻译及目录 JSON 校验通过。

| 无窗口指标 | 样本数 | p50 | p95 |
| --- | ---: | ---: | ---: |
| `sessionStartup` | 2 | 50.235 ms | 52.238 ms |
| `historyRead` | 13 | 52.770 ms | 57.108 ms |
| `rpcReassembly` | 12 | 2.483 ms | 3.149 ms |
| `streamFlush` | 40 | 0.002 ms | 0.004 ms |
| `processShutdown` | 3 | 0.388 ms | 0.767 ms |

采样 7 次，观测到的同时总 physical footprint 峰值约 44.33 MiB，帮助进程自身峰值约 32.44 MiB；不完整总量样本 0 次。该总量包括被采样到的模拟 RPC 子进程，不包含真实 OMP、MCP 或 WebKit。短回放的这些峰值仅用于后续同口径比较。

这些结果是单次 Debug 无窗口回放的观测值，没有优化前后对照，也不能换算为真实 OMP、GUI 内存预算或界面 p95。启动耗时不含真实模型提供商和扩展初始化；大帧计时不覆盖完整传输；本次历史数据约 2.44 MiB，不能代表带大型工具结果的全部历史。

## GUI 验证与历史恢复修复（Dev 0.1.18 / 19）

启动已获得 owner 明确授权。`tests/acceptance/runtime.py` 只在显式运行时启动本 worktree 的 Dev app，不由 `make build` 调用。每次建立新的 `build.noindex/omp-p0-live/<run>/`，包含独立聊天库、工作区、偏好及 OMP 配置。OMP 启动要求可选择的模型，因此隔离配置只定义 `http://127.0.0.1:9/v1`、无需认证的测试模型；只执行原生状态和能力请求，不发起模型推理。

```sh
make build
python3 tests/acceptance/runtime.py
# 等待输出 inspection，完成窗口检查后：
touch build.noindex/omp-p0-live/<run>/finish
```

实际窗口使用已有 SwiftUI/AppKit、ThreadWindow、聊天列及文件预览。沿用 CaptureRun 跳过账号后台服务和全局模型/MCP 发现，因此该隔离窗口负载与正常用户配置下的完整启动不同。固定数据为两份各 128 条消息的聊天、一份 5,000 轮 / 10,000 条消息的旧格式历史，以及包含 60 个公式、表格和代码块的 Markdown 预览。新版负载仅在冷读取开始时插入长聊天，防止启动预建聊天列提前读取它。

首轮旧历史加载与布局循环用时约 55.19 秒。三个主线程卡顿采样均指向 `ThreadRuntime.install` 逐条插入结束标记及 `entries.didSet` 重建索引。修复将缺失标记、结束时间、运行中断状态集中恢复，再一次发布 turns/entries；使用 turn/entry 索引及位置二分查找，保留现有标记身份、记录顺序和分段保存格式。

新增 8 项生产代码回归覆盖 10,000 条消息、运行中断、缺失完成时间、已有结束标记、逐轮顺序、落盘和分段重开。全部 110 项 P0 生产检查、2 项默认指标检查、11 项资源归属检查、25 项 eval/runtime、54 项 todo 同步检查通过。万条消息混合恢复的最终无窗口观测约 343 ms；5 秒回归护栏仅用于拦截数十秒卡顿，不代替 800 ms 首屏目标。

GUI 检查确认 zh-Hans 侧栏与时间线展示压缩状态；原生编辑框可保留中文草稿，⌘2 / ⌘1 切换后草稿仍在。预览能展示公式、表格与代码。该检查不是输入法组合、VoiceOver 语音或输入到字形呈现的延迟认证。

详细归档：[修复前 GUI](../evaluations/2026-10-16-p0-live/before-recovery-fix.json)、[修复后 GUI](../evaluations/2026-10-16-p0-live/after-recovery-fix.json)、[恢复热点证据](../evaluations/2026-10-16-p0-live/recovery-profile.json)、[最终无窗口回归](../evaluations/2026-10-16-p0-live/headless.json)。原始逐进程数据和采样栈留在本地构建目录，归档去除 PID。

第一次修复后 GUI 观察为：长历史加载加一次布局循环 829.17 ms（单次）；`chatSwitch` 的 run-loop p95 为 38.19 ms；100 次切换和 20 次预览后，已归属 GUI + OMP 的同时内存中位数从 500.28 MiB 到 513.91 MiB，增量 13.62 MiB，小于该测量范围的 50.03 MiB 预算。WebKit 完整归属未知，整应用内存验收结果仍为 `null`。

该轮两个空闲阶段的 GUI 平均 CPU 为单核 2.07% / 2.49%，超过 1% 目标。约 1 秒的高 CPU 突发占主要开销；不能以约 0.04% 的采样点中位数替代平均值，也不能删除突发样本后声称通过。窗口活动和可见性仅在阶段起点记录，期间并非受控前台环境，后续另做复测和突发采样。

本机 `omp/18.3.2` 实际支持本轮的协议协商、`get_state`、`get_subagents` 和事件订阅，返回 settled；`cancel_subagent` / `steer_subagent` 探测返回不支持。这与模拟对端的支持矩阵分别存档。状态示例中的压缩文案由 GUI 注入展示，未执行真实压缩或子代理任务。

## P0 剩余验收

以下项目继续留在 P0；本轮不是因为缺少 GUI 启动授权而暂停。

1. 用 Instruments 和实际屏幕呈现验证输入、缓存聊天首屏、万条历史冷首屏及流式事件至显示的 p95；run loop、模型更新及一次布局循环只能辅助定位。
2. 补齐属于本应用的 WebKit/XPC 进程证据、配置了 MCP 的运行负载，并锁定 GUI、OMP、MCP、预览引擎的绝对内存预算。当前系统的 `sample` 未提供可确认的 Responsible PID，未将其他应用的 WebKit 加入统计。
3. 验证真正旧版/新版 OMP、活跃子代理/原生队列、待答对话框、真实压缩/重试/后台任务、睡眠唤醒及损坏历史的回收与恢复。
4. 复现并解释跨轮次的空闲 CPU 突发，完成受控前台及后台测量。
5. 完成英文、VoiceOver、输入法组合、窄窗口和减少动态效果的完整交互验收。中文状态注入仅验证 GUI 展示，不等于真实压缩流程验证。

未配置的角色应省略并列为未测量，不能写成零占用。上述性能验收关闭后进入 P1 原生 steering/follow-up。本轮作为一个提交快进到 `codex/omp-native-roadmap`，主检出切换到该计划分支；`main` 不变，任务 worktree 留存。
